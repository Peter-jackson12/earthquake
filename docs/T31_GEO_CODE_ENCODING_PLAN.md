## 0. 요약

1. 질문: `geo_level_1/2/3_id`를 (a) 범주형(원핫 또는 LightGBM native categorical)으로 넣을 때와 (b) **정수 값 그대로 수치 열 3개**로 넣을 때 층화 CV Macro F1·등급별 지표·3→1/3→2와 **계산량(학습/예측 시간, 피크 메모리·행렬 크기, 모델 크기)** 이 어떻게 다른가. 가이드는 지역 코드의 숫자 크기에 의미가 없다고 하므로, 수치 표현은 "의미 있는 거리"가 아니라 **임의 순서의 정수 축**을 트리/선형 모델이 어떻게 쓰는지 보는 대조군이다.
2. **이미 측정된 셀(층화)**: LR 원핫(LR-C 0.688687), DT 원핫(0.594238), RF 원핫 mf=0.1(0.628992), GBC 원핫 mf=None(0.612109), LGBM 원핫(T4 O 0.669847 / T9 P 0.669966), LGBM native(T8 N 0.699342). **비어 있는 셀**: 모든 모델의 "지역 3열 수치 정수" 팔. 계산량은 기존 기록이 통제되지 않은 환경(n_jobs=2, 동시 작업 가능)이라 **어떤 셀도 그대로 비교에 쓸 수 없다**(같은 LGBM 설정이 41.6초 대 97.7초로 기록됨, §3.3).
3. 기본안: 모델 5종(LR, DT, RF, sklearn GBC, LGBM) × 지역 표현. **신규 수치 팔 25 fit + 원핫/native 팔을 같은 환경에서 재적합 30 fit = 완료 55 fit**, 시도 상한 59. 모든 학습·예측을 **단일 스레드**로 고정하고 fit마다 별도 프로세스에서 시간을 재며, 메모리는 별도 감시 프로세스의 20 ms 샘플링으로 잰다(§6.2). `OH`와 `NUM`은 같은 CSR 컨테이너를 쓰고 어떤 팔도 희소 행렬을 밀집화하지 않는다(§2.4). 예열 1회와 DT 반복 측정 4회는 측정 전용 실행으로 fit 수와 별도다(§6.1). RF sqrt 팔은 제외했다. 잠정 예상 시간 약 45~90분(**미측정**, §7.4).
4. 판정은 사전 고정 **기술 판정**이다. 모델별로 ΔMacro F1(평균), Fold 승수(5개 중), 3등급 Recall 변화, 3→1·3→2 변화, 계산량 비율을 보고하고 `NUM_HIGHER / NUM_LOWER / NO_MATERIAL_DIFFERENCE / MIXED` 태그를 붙인다. 임계값은 제안값이며 §14에서 승인한다. 최종 모델 교체·후보 승격은 하지 않는다(공식 개인 최종 모델은 T0 LR C=1 유지).

## 1. 평가 기준과의 정합

- 주 평가 분할은 `docs/RESEARCH_STATUS.md` "평가 기준"과 AGENTS의 2026-10-16 규칙을 따른다. 이 설계는 분할·주지표·최종 선택 절차를 바꾸지 않는다. 주지표는 labels=[1,2,3] Macro F1, Fold 평균과 표준편차(ddof=1)이며 풀링(pooled) 지표와 구분한다.

## 2. 한 요소 정의 — 지역 코드 표현만 바꾼다

모든 팔에서 같은 것: 개발 208,480행, Fold 배정(`load_development()`가 돌려주는 저장 Fold), 입력 38열 전부(삭제 없음, 특수값 age 995·0 보존), 지역 외 열의 인코딩, 분류기와 모든 하이퍼파라미터·`random_state`, 결정 규칙(확률 argmax), 가중치 없음, 재표집 없음, 임계값 조정 없음, early stopping 없음, 튜닝 없음. 바꾸는 것은 **`geo_level_1_id`, `geo_level_2_id`, `geo_level_3_id` 세 열의 표현뿐**이다(세 열을 함께 바꾸며, 열별 개별 변환은 범위 밖).

### 2.1 표현 정의

| 표현 | 정의 | 어휘/통계 fit |
|---|---|---|
| `OH` 범주형(원핫) | v1.0.1 `OneHotEncoder(handle_unknown='ignore', sparse_output=True, float32)`. 지역 3열은 문자열 범주(`normalize_features`가 `astype(str)`) | 학습 Fold의 값만 어휘로 학습, 미관측은 전부 0 |
| `NAT` 범주형(LightGBM native) | T8 N 그대로: `OrdinalEncoder`(학습 Fold 어휘, 미관측→NaN) 코드 + `categorical_feature` 선언 | 학습 Fold만 |
| `NUM` 수치 | 지역 3열을 **원본 정수 값 그대로** `float32` 숫자 열 3개로 입력(`int(str)` 변환, 통계 학습 없음). 최대값 < 2^24이므로 float32가 정수를 정확히 보존함을 `prepare`가 확인. 범주형 어휘·원핫·순서 코드 없음 | 통계 fit 없음(LR만 §2.3의 표준화) |

- `NAT`의 `OrdinalEncoder` 코드는 문자열 정렬 순서(`'10' < '2'`) 코드이며 `NUM`의 정수 값과 **다른 순서**다. `NUM`은 정수 값 자체를 쓴다. 이 구분을 보고서에 적는다.
- 학습 Fold에 없는 지역: `OH`는 0벡터, `NAT`는 NaN, `NUM`은 그 정수 값을 그대로 받는다(미관측 개념이 없음). 층화 Fold에서의 미관측 행 수를 Fold별로 기록하고(`preprocess.validate_fold_preprocessing`의 `unseen_validation_categories`와 같은 정의), 이 하위집단의 F1을 기술 통계로 보고한다.
- `preprocess.py` v1.0.1은 수정하지 않는다. `NUM` 경로는 실험 코드(`experiments/geo_code_encoding/`, 제안)에서 `make_preprocessor`와 동일한 `ColumnTransformer`를 쓰되 `categorical` 블록에서 `GEO`를 빼고 지역 3열을 수치로 추가한다. 트리 모델(DT/RF/GBC/LGBM)은 별도 `geo_numeric` 블록(변환 없음), LR은 기존 `numeric` 블록(수치 5열)에 합쳐 같은 `StandardScaler`(학습 Fold fit)를 쓴다. 열 이름 기준 비교(§8.4)는 이 블록 이름을 매핑해 수행한다. `FeatureSchema`가 지역을 문자열로 정규화하므로, 정수 변환은 그 뒤의 stateless 함수(모듈 최상위 함수; 람다 금지, 직렬화를 위해)에서 한다.
- 입력 컨테이너(CSR/dense)는 §2.4에서 팔별로 고정한다. 희소 행렬 전체 `.toarray()`는 어디서도 하지 않는다(AGENTS).

### 2.2 모델별 팔과 고정 설정 (기존 기준선과 동일)

| 모델 | 팔 ID | 지역 표현 | 그 밖의 고정(기존 기준선 그대로) | 연령 정책 |
|---|---|---|---|---|
| LR | `LR_OH` / `LR_NUM` | OH / NUM | T1 C = LR-C: lbfgs, C=1, max_iter=1500, tol=1e-4, random_state=42, 수치 5열(+NUM은 지역 3열) `StandardScaler`(학습 Fold) | C(995→학습 Fold 비995 중앙값 + `age_is_995`) |
| DT | `DT_OH` / `DT_NUM` | OH / NUM | `configs/baseline.json` dt: max_depth=12, min_samples_leaf=5, random_state=42 | A(원값) |
| RF | `RF_OH` / `RF_NUM` | OH / NUM | `configs/feature_budget.json` rf: 100 trees, max_depth=20, min_samples_leaf=2, **max_features=0.1**, random_state=42 | A |
| GBC | `GBC_OH` / `GBC_NUM` | OH / NUM | `feature_budget.json` gbc: 100 stages, lr 0.1, max_depth 3, **max_features=None**, random_state=42 (`sample_weight` 없음) | A |
| LGBM | `LGBM_OH` / `LGBM_NAT` / `LGBM_NUM` | OH / NAT / NUM | T4 파라미터(`experiments/model_families/config.json` models.LGBM: 300 rounds, lr 0.05, num_leaves 31, max_bin 255, `deterministic=true`, `force_col_wise=true`, seed 42); **텍스트 범주 8열은 세 팔 모두 native**(T9 P와 T8 N이 쓰는 방식) | C |

- **LGBM 세 팔의 정의가 핵심이다.** `LGBM_OH`는 T9 P(지역 원핫 + 텍스트 8열 native), `LGBM_NAT`는 T8 N(지역·텍스트 모두 native), `LGBM_NUM`은 **N과 같은 39열 값에서 지역 3열(28–30)을 정수 값으로 바꾸고 `categorical_feature`에서 그 3열만 제외**(텍스트 8열 31–38은 선언 유지)한 것이며, 컨테이너는 `LGBM_OH`와 같은 CSR이다(§2.4). 세 팔의 텍스트 표현이 같으므로 팔 간 차이가 지역 표현 하나로 한정된다. T4 O(텍스트 원핫)는 T9에서 P와 사실상 동일(층화 ΔF1 +0.00012, 3→1 303→300)이므로 이 비교의 기준으로 쓰지 않고 인용만 한다.
- 모델 안의 `n_jobs`·스레드는 §6.1의 단일 스레드로 통일한다(기존 기준선의 n_jobs=2와 다름; 파라미터 변경이 아니라 측정 환경 고정이다. RF·LGBM은 스레드 수가 학습 결과를 바꾸지 않아야 하며 §8.3의 대조로 확인한다).
- 연령 정책은 **모델별로 기존 기준선을 유지**한다(LR·LGBM은 C, DT·RF·GBC는 A). 이는 변수가 아니라 재사용을 위한 고정이다. 서로 다른 모델 사이의 직접 순위 비교는 하지 않는다.
- 하이퍼파라미터는 `OH`에서 정해진 값 그대로이며 `NUM`/`NAT`에 맞춰 다시 조정하지 않는다. 따라서 결과는 "고정된 하이퍼파라미터 아래의 표현 변경 효과"이며 각 표현의 최적 성능이 아니다.

### 2.3 LR의 표준화

`LR_NUM`에서는 지역 3열이 raw로 최대 약 10^4 규모라 lbfgs 수렴을 해치므로, 기존 수치 5열과 같은 방식(`StandardScaler`, 학습 Fold fit)으로 지역 3열도 표준화한다. 이 표준화는 `NUM` 표현의 일부로 기록한다(단조 변환이며 트리 모델 결과에는 영향이 없어 트리 팔에는 적용하지 않는다). 수렴 경고·`n_iter`는 결과로 기록하며 `max_iter`를 올리거나 재시도하지 않는다.

### 2.4 입력 컨테이너(CSR/dense) 사전 고정

- **코드로 확인한 사실:** `preprocess.make_preprocessor`의 `ColumnTransformer`는 `sparse_threshold=1.0`이고, 동결 환경 sklearn 1.8.0(`compose/_column_transformer.py`)은 하위 변환기 출력에 희소가 하나라도 있으면 `density < sparse_threshold`일 때 희소로 쌓는다. 텍스트 8열 원핫(희소)이 모든 sklearn 팔에 남으므로 지역 블록만 수치로 바꿔도 **`NUM` 출력은 CSR float32**다(밀도는 1 미만이며 값은 미측정). 즉 `NUM`을 dense로 가정한 초안 서술은 틀렸다.
- **원칙:** `OH`와 `NUM`은 같은 컨테이너를 쓴다. 트리의 희소/밀집 분할 경로 차이와 행렬·메모리 차이가 지역 표현 효과에 섞이지 않게 하기 위함이다.
- **LR, DT, RF, GBC:** `OH`·`NUM` 모두 위 `ColumnTransformer`가 낳는 CSR float32 그대로다. `sparse_threshold`를 바꾸지 않고 밀집 변환도 하지 않는다.
- **LGBM:** `LGBM_OH`(T9 P)는 CSR(기존 코드 그대로). `LGBM_NUM`은 `LGBM_OH`와 같은 CSR로 고정한다(N과 같은 39열 값을 `scipy.sparse.csr_matrix`로 감싼 것이며 밀집화가 아니다; `zero_as_missing=false`라 암묵적 0은 값 0이고, T9 소표본 확인이 CSR/dense 예측 일치를 보였다). `LGBM_NAT`(T8 N)은 기존 코드 그대로 dense 39열이며, 기존 OOF 대조(§8.3)를 위해 바꾸지 않는다. 따라서 **`LGBM_NUM` vs `LGBM_NAT`의 계산량 비교는 컨테이너 차이가 섞이므로 `CONTAINER_CONFOUNDED`로 표시**하고, 계산량 태그는 `LGBM_NUM` vs `LGBM_OH`에만 붙인다. 컨테이너 효과를 직접 보려면 선택 보조 팔 `LGBM_NUM_DENSE`(N과 같은 dense 컨테이너, 지역 3열 정수; 밀집 변환 없이 처음부터 dense 39열로 구성; 승인 항목 18)를 쓴다.
- **금지:** 어떤 팔도 희소 행렬을 `.toarray()`로 밀집화하지 않는다. 기록하는 것은 희소 속성(shape, nnz)에서 계산한 밀도와 밀집화 가정 크기 추정치뿐이다. 팔·Fold별 형식, 열 수, nnz, 밀도 `nnz/(행×열)`, 저장 크기를 결과에 기록하고 `prepare`/감사가 이 고정과 일치함을 확인한다.

## 4. 모델별 해석 차이 (가설이며 판정 규칙이 아니다)

사전 기대를 적어 두되 판정에는 쓰지 않는다. 결과가 이 기대와 달라도 그대로 보고한다.

- **LR:** 로지스틱 회귀는 입력의 선형 결합이므로 정수 코드는 "ID가 클수록 로짓이 일정하게 변한다"는 **단조 효과 하나(열당)** 로만 들어간다. 지역 코드의 크기에 의미가 없으므로 이 가정은 구조적으로 잘못되었고, 원핫이 지역별 개별 계수(약 1.2만 개)를 주는 것과 표현력이 크게 다르다. 지역 열을 모두 제거하면 0.4579, geo3만 제거하면 0.6531(T6R)이었다. `LR_NUM`은 제거 쪽에 가까울 것으로 기대하되(가설), 이 설계에서 확인할 대상이다. 계산량은 열 수가 약 1.2만 → 약 70으로 줄어 크게 낮을 것으로 기대한다. 지역 열 제거 실험의 효과 크기가 매우 커서 0.003 임계가 LR에서는 사실상 판별력이 없을 수 있으므로, LR은 효과 크기를 그대로 서술하고 태그는 보조로만 쓴다.
- **DT/RF/GBC(sklearn, 정확 분할):** 트리는 `ID ≤ t` 임계 분할을 쓰므로 임의 순서의 정수 축에서도 구간을 잘라 지역 묶음을 만들 수 있다. 다만 깊이가 제한돼 있어(DT 12, RF 20, GBC 3) 임의 지역 부분집합을 만들려면 분할이 여러 번 필요하다. 원핫은 단일 분할로 특정 지역을 분리하지만 희소 열이 1.2만 개라 후보 특성 추출(RF mf=0.1은 약 1,260개, sqrt는 약 112개)에서 정보 있는 열이 뽑힐 확률이 낮다(T0의 RF sqrt 0.3577이 극단적으로 낮은 이유로 의심되나 미확정). 따라서 `RF_NUM`은 열 수가 약 70이라 **후보 특성 수가 크게 달라진다**(mf=0.1 → 약 7개). 이것은 표현 변경에 불가피하게 딸려 오는 효과이며 순수 정보량 효과로 해석하지 않는다(T16의 같은 경고를 따름). 후보 특성 수 민감도 팔은 두지 않는다: sqrt 팔은 원핫이 퇴화 설정(CV 0.3577, 3→1 2건; 후보 약 112개/1.2만 열)이라 이 목적에 부적합하고, `max_features` 상향 팔은 한 요소 정의를 바꾸므로 범위 밖이다(§13.2).
- **LGBM(히스토그램 분할):** 수치 열은 `max_bin=255` 구간으로 이산화한다. `geo_level_3_id`의 고유값이 255개를 넘으면 **인접한 ID가 같은 bin으로 묶여** 지역 단위 해상도가 줄어든다(`geo_level_2_id`도 마찬가지일 수 있음). native는 범주 자체의 부분집합 분할(`max_cat_threshold=32` 등 기본값)과 범주 보존 규칙을 쓴다. 각 지역 열의 학습 Fold 고유값 수를 기록해 이 해상도 손실을 정량화한다. 대규모 범주(지역 3)의 native 이득(+0.029)은 지역별 부분집합 분할을 한 번에 할 수 있기 때문일 수 있으나, geo2 Group에서 반대로 낮아진 점(0.5457)은 학습 지역에 맞춘 분할일 가능성을 의심하게 하나 원인은 확인되지 않았다. 이 설계는 geo2를 새로 평가하지 않는다.
- **일반 주의:** 층화 CV는 같은 지역이 학습·검증에 모두 있으므로, 수치 정수 축에서의 구간 분할이 "지역 외우기"로 기능해도 점수가 올라간다. 따라서 `NUM`이 좋더라도 그것을 "숫자 크기에 의미가 있다"는 증거로 해석하지 않는다. 지역 일반화는 이 실험이 보지 못한다(§13).

## 5. 비교 질문의 구성 (모델별 짝)

모든 비교는 **같은 모델, 같은 Fold 쌍**이다.

| 모델 | 주 비교(P1) | 보조 비교 |
|---|---|---|
| LR, DT, RF, GBC | `*_NUM` vs `*_OH` | — |
| LGBM | `LGBM_NUM` vs `LGBM_OH` (수치 vs 원핫) | `LGBM_NUM` vs `LGBM_NAT` (수치 vs native; 컨테이너 차이가 섞여 계산량은 `CONTAINER_CONFOUNDED`), `LGBM_NAT` vs `LGBM_OH`(기존 짝 재확인) |

"범주형"은 `OH`와 `NAT` 두 변형을 포함하며, LGBM에서는 두 변형 모두와 수치를 비교한다. 모델 간 순위는 연령 정책·하이퍼파라미터가 달라 비교하지 않는다.

## 6. 계산량 측정 사양 (사전 고정)

### 6.1 환경 고정

- 실행 환경은 동결 환경: Python 3.13.5, numpy 2.3.5, pandas 2.2.3, scipy 1.17.0, scikit-learn 1.8.0, lightgbm 4.6.0, joblib 1.5.3, threadpoolctl 3.6.0, psutil 7.2.2(동결 venv에 설치돼 있음을 확인; `local_reproduction/20261014_01/venv`). 설치·변경 없음. `prepare`가 버전을 기록하고 불일치하면 중단한다.
- **단일 스레드:** 환경 변수 `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `NUMEXPR_NUM_THREADS=1`을 프로세스 시작 전에 설정하고 `threadpool_limits(1)`로 확인한다. RF/LGBM `n_jobs=1`(LGBM은 `num_threads=1`), 외부 병렬 없음. 병렬도는 0단계(모든 단계 직렬)다. AGENTS의 "한 단계만 병렬" 규칙을 이 실험에서는 병렬 0으로 충족한다.
- **fit 1개 = 새 프로세스 1개**(격리). 프로세스는 데이터 적재 직후 메모리(현재값과 `peak_wset`)를 기록하고, 인코딩 → 학습 → 예측을 수행한 뒤 저장(체크포인트) 전에 측정을 마친다. 저장·SHA·재로딩 검증은 측정 구간 밖이다. 메모리 감시는 별도 프로세스가 하며(§6.2) 학습 병렬이 아니다. 측정 대상 프로세스는 계속 단일 스레드다.
- 실행 전 조건: 다른 학습·무거운 작업 프로세스가 없음을 실행 주체가 확인하고(상위 CPU 프로세스 목록 기록), fit 직전 5초 동안 시스템 CPU 사용률 ≤ 10%임을 확인한다. 초과하면 최대 60초 대기 후 `noisy` 플래그로 기록하고 진행한다(결과를 버리지 않고 표시). 전원 계획(`powercfg /getactivescheme`)·CPU 모델·논리 코어·RAM·OS 빌드를 `preflight`에 기록한다(읽기 전용 명령). 노트북이라면 AC 전원 연결을 확인한다(승인 항목 6).
- **실행 순서와 교대:** 각 모델의 **Fold 0은 항상 `OH`(LGBM은 `OH`→`NAT`) → §8.3 대조 → `NUM`** 순서이며 대조를 통과하기 전에 같은 모델의 `NUM`을 시작하지 않는다. 교대는 Fold 1부터 적용한다: Fold 1·3은 `NUM`→`OH`, Fold 2·4는 `OH`→`NUM`(LGBM은 `OH`/`NAT`/`NUM` 순서를 Fold 1부터 회전). 시간 경과(열 제한·캐시)로 인한 편향을 한쪽 팔에 몰지 않기 위한 것이다.
- **예열과 반복 측정(측정 전용 실행):** 실제 측정 전에 `DT_OH` Fold 0을 1회 예열 실행해 결과를 폐기한다(로그는 보존). 시간 재현성을 위해 `DT_OH`·`DT_NUM`의 Fold 0을 각 2회 추가 실행하고(총 4 프로세스) 같은 입력의 시간 변동계수를 보고한다. 이 5회(예열 1 + 반복 4)는 분류기를 학습하지만 OOF·판정에 쓰지 않고, 연구 fit 수(55/59)와 **별도로** 세며 재시도하지 않는다(승인 항목 20).

### 6.2 지표 정의

| 지표 | 정의 | 도구 |
|---|---|---|
| 인코딩 시간 | 학습 Fold 전처리기 `fit_transform` + 검증 `transform` 시간(초). (a) 정규화 단계(`FeatureSchema`)와 (b) 표현 변환 단계(원핫/순서 코드/`str→int`·표준화)를 나눠 기록한다. `NUM`은 정규화가 지역을 문자열로 만든 뒤 다시 정수로 바꾸는 왕복 비용이 (b)에 들어가므로 수치 우선 파이프라인의 실제 비용보다 크다. 인코딩 시간을 순수 표현 비용으로 해석하지 않는다 | `time.perf_counter` |
| 학습 시간 | 분류기 `fit`만(초) | `perf_counter`, 보조로 `time.process_time`(CPU 시간; CPU/Wall 비로 경합 점검) |
| 예측 시간 | 검증 41,696행 `predict_proba`(초)와 1,000행당 환산. 모든 팔이 **sklearn 래퍼 `predict_proba`를 단일 스레드로 같은 호출 경로**로 부른다(LGBM도 `booster.predict` 직접 호출 금지). 희소(OH/NUM)와 dense(NAT)는 LightGBM 내부 예측 경로가 달라 해석에 반영한다 | `perf_counter`. 전처리 `transform` 시간은 인코딩 시간에 포함해 별도 보고 |
| 종단 시간 | 인코딩 + 학습 + 예측 | 합 |
| 메모리 | **주 지표 = 감시 프로세스 샘플링 구간 증가분.** 측정 대상(자식)과 별개의 감시 프로세스가 20 ms 간격으로 `psutil.Process(pid).memory_info().rss`를 샘플링한다. 자식은 구간(인코딩, 학습, 예측)의 시작·끝 `perf_counter` 값을 기록하고(Windows QPC가 프로세스 간 공통임을 `preflight`가 확인), 구간별 증가분 = 구간 내 샘플 최대 − 구간 시작 시점 샘플. 보고하는 지표는 인코딩+학습 구간 증가분(주)과 예측 구간 증가분. **보조:** 적재 직후의 `peak_wset`과 학습·예측 직후의 `peak_wset`(되돌릴 수 없는 프로세스 고수위이므로 증가분 = 이후 peak − 적재 직후 peak, 0 이하이면 `FLOOR_LIMITED`), `peak_pagefile` | `psutil` (Windows). 이전 기록(`model_families`)은 `peak_wset`만 썼다 |
| 행렬 크기 | 학습 행렬의 열 수, nnz(희소), 형식(CSR/dense, §2.4 고정과 일치), 저장 크기(희소: `data+indices+indptr` 바이트; dense: `nbytes`), 밀도. **밀집화 추정치만 계산하고 실제 `.toarray()`는 하지 않음** | `scipy.sparse` 속성 |
| 모델 파일 크기 | 분류기 산출물 바이트: sklearn은 `joblib.dump(model, compress=0)`, LGBM은 모델 텍스트(`model_to_string`)와 `joblib`(LGBM 분류기) 둘 다. 전처리기 `joblib` 바이트는 따로. 합계 = 배포에 필요한 파일 | 파일 크기 |
| 기타 | LR `n_iter`·수렴 경고, 트리 수·노드 수(sklearn `tree_.node_count` 합), LGBM 실제 트리 수·모델 텍스트의 지역 열 분할 수 | 모델 내부 속성 |

- **메모리 하한 규칙(사전 고정):** 구간 증가분이 16 MiB 미만이거나 `FLOOR_LIMITED`인 쌍은 메모리 계산량 태그에서 제외하고 값만 보고한다. 측정 하한 때문에 `LOWER`/`SIMILAR`가 결정되는 것을 막기 위함이다. 20 ms보다 짧은 일시 할당은 놓칠 수 있어 샘플링 증가분은 하한 추정이며(`SAMPLING_LIMITED` 주석), `rss`/`peak_wset`은 OS 페이징의 영향을 받는다. 두 지표의 불일치는 숨기지 않고 함께 보고한다.
- 시간 비율은 Fold별로 `NUM/기준`을 계산하고 **중앙값과 Fold별 값 범위**를 보고한다. 5개 Fold 쌍이라 통계적 추론은 하지 않으며 기술 통계다.
- 모든 값은 측정 환경의 관측치이며 통제된 하드웨어 벤치마크가 아니다. 다른 기계·스레드 수·라이브러리 버전으로 일반화하지 않는다. 학습 시간에 인코딩·저장·재로딩 시간을 섞지 않는다.

## 7. 실행 설계

### 7.1 단계

1. **구현·합성 테스트:** `experiments/geo_code_encoding/`(`config.json`, `run.py`), `tests/test_geo_code_encoding.py`(합성 데이터만). `python -m unittest discover -s tests -v` 전체를 실행하고 pass/skip을 구분해 기록한다. T8/T9/`baseline.py`/`experiments.age995`의 기존 코드는 **import만** 하고 수정하지 않는다. `preprocess.py` 불변.
2. **`preflight`(분류기 학습 0회):** 전처리기 `OH`/`NUM` 행렬을 Fold 0에서 만들어 §8.4의 일치 검사, 열 수·nnz·형식·밀도(§2.4), 지역 열 고유값·최대값(< 2^24)·미관측 건수, 프로세스 간 시계 공통성(§6.2)을 기록한다. 기존 OOF 7개(대조 6 + 인용 1)와 `development.csv`, `split_manifest.csv`(층화만 사용; geo2/geo1 manifest는 쓰지 않음)의 SHA를 읽기 전용으로 확인한다.
3. **`prepare`:** 설계·소스·환경·SHA를 봉인(`design.json`, `design_seal.json`). 봉인 후 설계·코드·설정은 실행 중 변경하지 않는다. 이 문서도 봉인 대상이다.
4. **`fit-all`:** 단일 실행권을 받은 한 주체만 실행한다. 모델 순서는 LR → DT → GBC → RF → LGBM(저비용 먼저, LR 완료 후 시간 추정 갱신). 같은 Fold를 두 주체가 학습하지 않는다. 각 모델의 Fold 0은 `OH`(`NAT`) → 대조(§8.3) → `NUM` 순서다(§6.1). 대조 실패 시 산출물은 폐기하지 않고 보존하며 봉인 설계는 바꾸지 않는다; 설계 개정은 새 ID로만 한다.
5. **`finalize`:** 팔·분할별 OOF 조립, 지표, 판정, 계산량 집계(`analysis.json`).
6. 독립 감사 → 공개 집계 보고 → 메인이 커밋·푸시(§11).

### 7.3 병렬도

학습은 완전 직렬이며 스레드도 1이다(§6.1). 이전 연구의 n_jobs=2~4와 다른 점은 시간이 최대 약 2배 늘 수 있다는 것이다. 학습 단계 외의 해시·백업 복사도 순차로 한다.

## 8. 체크포인트·원장·SHA·재개·대조 확인

AGENTS "머신러닝 연구 운영 순서"를 따른다.

### 8.1 Fold(fit) 단위 저장

각 fit 완료 직후 분류기 산출물(sklearn `joblib`, LGBM 모델 텍스트), 전처리기 상태(`joblib`), 검증 예측 확률(CSV gzip, `%.17g`), Fold JSON(지표·계산량·환경·경고·`noisy` 플래그), 로그를 저장하고 SHA-256을 `ledger.json`에 기록한다. 저장 직후 (a) 모델·전처리기 재로딩 확률 차이 ≤ 1e-12와 등급 동일(단일 스레드 추론), (b) CSV를 `float_precision='round_trip'`으로 읽어 정확 일치, (c) `backup/`로 복사해 SHA 일치를 확인한 뒤에만 `complete`로 기록한다. 저장 실패는 완료가 아니다. 완료 fit은 해시 검증만 하고 재학습하지 않으며, 중단 후 재개를 지원한다. 원본 실행 결과를 덮어쓰지 않는다. `RUNNING.lock`은 실제 실행 주체가 없음을 컨트롤 타워가 확인한 뒤에만 제거한다.

### 8.2 기존 OOF 보존

기존 OOF 7개(대조 6 + 인용 1)와 모델은 읽기 전용이다(해시만 확인). T31은 새 경로에만 쓴다. 기존 결과를 새 학습 결과로 소급하지 않는다.

### 8.3 대조 확인(기존 OOF와의 일치) — 각 `OH`/`NAT` 팔의 Fold 0에서 즉시 수행

- 트리/부스팅 모델(DT, RF, GBC, LGBM P/N): 재적합 확률이 기존 OOF 해당 행과 최대 절대차 ≤ 1e-9이고, 예측 등급이 같아야 한다. 단, 기존 확률에서 상위 두 값의 차가 2e-9 이하(두 값이 각각 최대 1e-9 어긋날 수 있으므로)인 동률 행의 등급 차이는 허용하고 그 건수를 기록한다(RF `predict_proba` 병렬 합산 순서 비결정성은 T14에서 관찰됨). **불일치하면 그 모델의 `NUM` 학습을 시작하기 전에 중단하고 보고한다**(자동 우회·허용오차 완화 금지). LGBM은 `deterministic=true`라 스레드 수가 달라도 같은 결과가 기대되지만 미확인이다. 단일 스레드 재적합이 기존 OOF(n_jobs=2)와 다르면 위 규칙대로 중단하고, 스레드 수를 기존 값으로 되돌릴지는 사용자가 결정한다.
- LR: 기존 OOF(`de43f997…`)는 다른 환경 산출물이고 교차환경 LR 차이가 알려져 있다. Fold F1 차이 ≤ 5e-4(제안)면 `PASS`, 초과하면 `DIVERGED_KNOWN_ENV`로 표시하되 중단하지 않고 진행한다. 검토자 계산상 LR C 설정의 원 환경 대 로컬 Fold F1 차이는 최대 3.6e-4이고 다른 LR 설정에서는 8.0e-4까지 관찰돼, 5e-4는 일반화하면 넘을 수 있다. 판정 기준은 어차피 같은 환경 재적합이다.
- LR 2차 대조(**참고 보고, 통과 필수 아님**): 같은 기계·venv의 로컬 재적합 `runs/age995_abc/C/lr`(SHA `0601965653…`)과 확률 최대 차이(제안 1e-6)와 등급 일치 여부를 기록한다. 이 로컬 재적합의 BLAS 스레드 설정이 단일 스레드와 같다는 보장은 없다. 같은 재적합 결과를 두 기준에 대조하므로 추가 fit은 필요 없다.
- **시점:** 각 모델의 Fold 0에서 `OH`(`NAT`) 재적합이 끝나고 저장·재로딩 검증을 마친 직후 대조하며, 통과해야 같은 모델의 `NUM` 첫 fit을 시작한다. 실패하면 산출물은 폐기하지 않고 보존하며 원장에 `CONTROL_FAILED`로 기록한다. 대조는 봉인 이후 `fit-all` 안에서 하므로(T8은 prepare 이전에 별도 대조) 실패는 중단·보고이고, 설계 개정은 새 ID로만 한다.
- 대조 결과는 팔별 `control_check.json`에 기록하며 연구 fit 수에 이미 포함된다(별도 대조 fit 없음).

### 8.4 팔 간 일치 검사(전처리 단계, 분류기 학습 아님)

각 Fold에서 `NUM` 행렬의 **지역 외 열**(수치·이진·텍스트 원핫·연령 정책 열)이 같은 학습 Fold로 만든 `OH` 행렬의 해당 열과 열 이름 기준으로 완전히 같고, `NUM` 지역 3열이 원본 정수 값과 일치하며(LR은 `numeric` 블록 `StandardScaler`의 `inverse_transform`이 원본 정수와 일치하고 수치 5열은 `OH`와 같은 값), 지역 외 어떤 통계도 검증 라벨/전체 개발 데이터에서 fit되지 않았음을 확인한다. LGBM `NUM`은 `NAT`와 지역 3열 값이 다르고(정수 값 대 문자열 순서 코드) 나머지 36열이 같아야 한다. 비교는 열 이름 기준 부분집합 CSR 비교(`(A != B).nnz == 0`)이며 전체 `.toarray()`는 없다. `LGBM_NAT`(dense)와의 비교는 36개 열 슬라이스만 CSR로 감싸 수행하고(밀집화가 아니라 희소 래핑) 컨테이너 차이는 §2.4에 따라 기록한다.

## 9. 판정 (사전 고정 기술 판정, 임계값은 제안값 — 승인 항목 4·5)

### 9.1 성능 지표

모든 지표는 층화 5-Fold, 같은 Fold 쌍에서 계산한다. 주지표는 Fold 평균 Macro F1.

- `Δ` = Fold 평균 Macro F1(`NUM`) − (기준). 기준은 §5의 짝(`OH`, LGBM은 `OH`와 `NAT` 각각).
- `wins` = 같은 Fold에서 `NUM` Macro F1이 기준보다 **엄격히** 큰 Fold 수(5개 중).
- `ΔR3` = 풀링 OOF 3등급 Recall 변화(분모: 실제 3등급 69,774건).
- 3→1, 3→2: 풀링 OOF 건수와 비율(분모 69,774), 기준 대비 변화.

### 9.2 성능 태그

| 태그 | 조건 |
|---|---|
| `NUM_HIGHER` | `Δ ≥ +0.003` **그리고** `wins ≥ 4` **그리고** `ΔR3 ≥ −0.01` |
| `NUM_LOWER` | `Δ ≤ −0.003` **그리고** `wins ≤ 1` |
| `NO_MATERIAL_DIFFERENCE` | `|Δ| < 0.003` |
| `MIXED` | 위에 해당하지 않는 나머지(예: `|Δ| ≥ 0.003`이지만 Fold 승수 2~3) |

- 임계 0.003은 이 저장소의 사전 기준(T12 등의 +0.003)을 따르는 제안값이다. Fold SD는 LR 약 0.0015, LGBM 약 0.003~0.0036, RF 0.0038, DT 0.0045, GBC 0.0051이라 트리 모델에서는 0.003이 Fold 변동폭 안이다. 그래서 Fold 승수 조건을 같이 요구한다. 어느 태그도 유의성이나 인과 주장이 아니다.
- **안전 플래그(태그와 별도, 양방향):** `SAFETY_3to1`은 비교하는 두 팔 중 풀링 3→1 건수가 상대 팔보다 **상대 +10% 넘게 그리고 절대 +30건 이상** 많은 팔에 표시한다(`NUM`이 많을 때뿐 아니라 기준 또는 `NAT`가 많을 때도 표시; LGBM은 모든 쌍). 이중 조건은 기존 3→1 건수가 DT 약 165, RF 약 187, LR 약 452로 팔마다 달라 상대 비율만으로는 소수 건수 변동이 잡히기 때문이다. 절대 30건은 제안값이며 대안은 10건이다(승인 항목 21). 3→1은 심각한 피해를 가장 낮게 예측하는 오류라 AGENTS가 모든 평가에서 점검하도록 한 항목이며, 이 플래그는 태그 `NUM_HIGHER`를 무효화하지 않고 병기한다. 가중치·재표집이 아니므로 증가 폭이 작을 것으로 기대하지만 결과가 아니다.

### 9.3 계산량 태그

| 지표 | 비율 | 태그 |
|---|---|---|
| 학습 시간, 예측 시간, 종단 시간, 메모리(인코딩+학습 구간 샘플링 증가분; 16 MiB 미만·`FLOOR_LIMITED` 쌍 제외), 모델 크기(분류기 산출물 + 전처리기), 학습 행렬 저장 크기 | 5개 Fold 비율 `NUM/기준`의 중앙값 | `LOWER` ≤ 0.5, `HIGHER` ≥ 2.0, 그 사이 `SIMILAR` |

- Fold별 비율 범위가 태그 경계(0.5 또는 2.0)를 걸치면 `BOUNDARY`를 병기한다. 열 수·nnz는 결정적 값이라 태그 없이 값만 보고한다. LGBM `NUM` vs `NAT`는 `CONTAINER_CONFOUNDED`라 태그를 붙이지 않고 값만 보고한다.
- 두 축(성능 태그 × 계산량 태그)을 모델별 표로 나란히 보여주되 "수치 표현이 더 낫다/원핫이 낫다"는 추천이나 채택 결론은 쓰지 않는다. 단일 시드·단일 환경의 기술 결과다.

### 9.4 판정과 무관한 보고

모든 팔의 결과를 판정과 무관하게 보고한다. 같은 Fold에서 여러 설정을 비교한 결과이므로 낙관적일 수 있다. 최종 모델 교체, 홀드아웃 평가, 새 후보 승격은 이 설계의 범위가 아니다(T29 별도).

## 13. 한계

1. **지역 일반화를 보지 못한다.** 층화 CV에서는 같은 지역이 학습·검증에 모두 있다. 수치 정수 축 분할이 지역 외우기로 기능해도 점수가 오를 수 있다. 미관측 지역(geo2/geo1 Group) 성능은 이 판정의 범위 밖이며 새로 측정하지 않는다. 기존 geo2 인용값은 팔이 달라 `NUM`과 직접 비교하지 않는다.
2. **하이퍼파라미터를 표현별로 다시 조정하지 않았다.** 고정값이 원핫에서 정해졌다면 `NUM`에 불리/유리할 수 있다. 특히 RF의 `max_features`는 열 수 변화로 후보 특성 수가 크게 달라진다(RF mf=0.1: 약 1,260 → 약 7). 차원이 통제된 순수 정보량 효과가 아니다. 후보 특성 수 민감도 팔은 두지 않았다: sqrt 팔은 원핫이 퇴화 설정(CV 0.3577, 3→1 2건)이라 표현 비교로 읽기 어렵고, `max_features` 상향은 한 요소 정의를 바꾼다.
3. **LGBM `NUM`은 `max_bin=255`에 묶인다.** 지역 3의 고유값이 많아 인접 ID가 합쳐진다. 이는 표현 효과의 일부이며 `max_bin`을 바꾸는 시험은 범위 밖이다.
4. **LR `NUM`은 표준화한 선형 단조 항**이라 구조적으로 제한적이다. 이 한계 자체가 결과의 이유이며 "수치 표현은 나쁘다"로 일반화하지 않는다.
5. **지역 3열을 함께만 바꾼다.** 열별 개별 변환(예: geo1만 수치)과 수치+원핫 병행은 범위 밖이다.
6. **단일 시드·단일 분할·단일 기계.** 모든 모델이 `random_state=42`이고 RF/LGBM의 시드 변동을 정량화하지 않는다. 계산량은 Windows 한 대의 단일 스레드 관측이며 Fold 쌍 5개로는 변동 추정이 약하다(재적합을 Fold 0만 하면 1쌍).
7. **연령 정책이 모델별로 다르다**(LR·LGBM C, 나머지 A). 모델 간 순위 비교 불가.
8. **재사용 OOF의 증거 수준이 다르다.** DT/RF/GBC 기존 OOF는 로컬 재적합(원 산출물 `BLOCKED`), LR은 환경 차이가 알려져 있다. 판정은 같은 환경 재적합을 기준으로 해 이 문제를 피하지만, "과거 보고 수치"와의 연결은 대조 확인에 의존한다.
9. **선택 통계.** 같은 Fold로 이미 여러 번 비교된 자료다. 독립 성능이 아니며 최종 모델 근거가 아니다.
10. **설계자가 확인하지 못한 것:** 층화 Fold별 지역 미관측 건수, 지역 열 고유값 수와 최대값(문서의 "약 1.2만"은 인코딩 열 수 12,593에서 역산한 근사), 텍스트 원핫 열 수(약 38로 가정), `NUM` 열 수(약 68~69, 지역 외 27~28열 + 지역 3 + 텍스트 원핫 약 38로 가정), LGBM 스레드 수 변경 시 확률 일치, `NUM` 행렬의 실제 밀도와 감시 프로세스 샘플링의 시계 공통성, 모든 시간 추정. (기존 OOF 7개의 SHA는 독립 검토자가 재계산해 일치를 확인했다; 설계자는 재계산하지 않았다.)
11. **컨테이너와 메모리 측정의 한계.** `OH`·`NUM`을 같은 CSR로 고정해 경로 효과를 맞췄지만, 이것은 sklearn의 희소 분할기를 약 70열 행렬에도 쓰는 것이라 "수치 우선 파이프라인이 자연스럽게 쓰는 dense 경로"의 계산량이 아니다. 같은 이유로 `LGBM_NUM` vs `LGBM_NAT` 계산량은 컨테이너가 섞인다. 메모리는 20 ms 샘플링의 하한 추정이며 16 MiB 미만 증가분은 비교에서 제외한다.
12. **인코딩 시간의 왕복 비용.** 공통 전처리(`normalize_features`)가 지역을 문자열로 만들기 때문에 `NUM`은 다시 정수로 바꾼다. 인코딩 시간은 순수 표현 비용이 아니다(§6.2에서 단계 분리).

## 14. 승인 필요 항목

1. 모델 범위: 기본(LR, DT, RF, GBC, LGBM = 필수 네 모델 + LGBM) vs 필수 최소(LR, RF, LGBM). 사용자 지시 최소는 LR·RF·LGBM이며 DT·GBC는 비용이 작아 포함을 권고한다.
2. 재적합 범위: 전 Fold(기본, 30 fit, 성능·계산량을 같은 환경 쌍으로 비교) vs Fold 0만(6 fit, 성능은 기존 OOF 사용·계산량은 1쌍).
3. RF sqrt 민감도 팔은 제외(원핫이 퇴화 설정). `max_features` 상향 등 후보 특성 수 민감도 팔도 범위 밖으로 둔다는 확인.
4. 성능 태그 임계: `|Δ|` 0.003, Fold 승수 4/5(하락은 ≤1/5), `ΔR3 ≥ −0.01`, 3→1 플래그는 상대 +10% **그리고** 절대 +30건(양방향; 항목 21).
