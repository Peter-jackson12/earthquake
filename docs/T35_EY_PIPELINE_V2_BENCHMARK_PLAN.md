## 1. 이 실험의 성격

- **재현 벤치마크이며 팀원 평가가 아니다.** 같은 파이프라인을 우리 공통 Fold에서 다시 계산해 기존 후보와 같은 지표로 놓는 것이 목적이다. 보고서는 "EY 새 노트북 파이프라인 층화 CV 재현 벤치마크"로 표기한다.
- **노트북은 읽기 전용이다.** 원본과 팀원 브랜치(EY·jjjjin·sy)는 수정·접근하지 않는다. 사본은 비공개 `source_copy/`에 SHA를 고정해 보존한다. 우리 실행기는 셀 28의 논리를 우리 코드로 옮겨 구현하고, 사본에서 AST로 추출한 원래 함수와 **비트 동일**함을 사전 점검에서 확인한다(§5).
- 새 방법·임계값 조정·결정 규칙 변경·홀드아웃 평가·최종 모델 변경은 없다. 예측은 `predict_proba` argmax다(노트북 `predict`와 같은 규칙).

## 4. 학습 예산·체크포인트·시간

- **신규 fit 10회**(Fold 5 × 팔 2). 시도 상한 **12 fit**: unit(=팔×Fold)당 시도 최대 2회, 수동 복구 최대 2 unit. 자동 재시도 0. 비교군 재학습 0, 탐색 0. 합성 데이터 프로브·단위 테스트 학습은 예산 밖이며 판정에 쓰지 않는다.
- **전체 CV**: 모든 수치는 개발 208,480행 전체의 5-Fold다. 표본 CV를 쓰지 않는다.
- **병렬 한 단계**: 모델 `n_jobs=4`(노트북 값과 같음). 특징 계산·평가·저장은 단일 스레드, Fold·팔 순차 실행. 희소 행렬과 `.toarray()`를 쓰지 않는다(밀집 DataFrame).
- **예상 시간(노트북 출력 기준, 미측정)**: 노트북 선택 단계(학습 166,784행)에서 L 0.4분, X 0.5분. 특징 계산은 T33 실측 Fold당 약 2초(구판 기준)라서, 합계 약 5~15분으로 본다. 첫 Fold 실측으로 갱신하며 추정이 틀려도 설계·판정은 바뀌지 않는다.
- **체크포인트**: Fold별 특징(검증 행렬 npz + 열 이름·dtype·SHA json, 학습 행렬은 SHA와 진단만)을 저장·재로딩 검증 후 원장에 기록한다. unit 완료 즉시 모델(L: LightGBM 텍스트, X: XGBoost JSON), 검증 확률 CSV(17자리 round-trip), Fold JSON을 저장하고 SHA를 `ledger.json`·`attempts.jsonl`에 기록, `backup/`에 복사한다. 재로딩 검증: 모델 파일을 다시 읽어 저장된 검증 행렬로 재추론한 확률이 L은 `atol=1e-12`, X는 `atol=1e-6`(float32 출력) 이내이고 예측 등급이 같아야 하며, CSV 재읽기는 정확 일치해야 한다. 완료 unit은 재학습하지 않고 해시만 검증한다. `RUNNING.lock`으로 중복 실행을 막는다. 봉인 뒤 코드·설정·계획은 바꾸지 않는다.

## 5. 사전 점검 (학습 없음, `prepare` 전 PASS 필수)

1. **원본 대조**: 비공개 사본의 셀 28에서 AST로 함수 `building_features`, `rate_table`, `make_features`, `to_matrix`, `make_weights`와 상수 `SEED`, `CAT_COLS`, `RATE_KEYS`, `NEW_FEATURES`, `ALL_FEATURES`만 추출해(그 외 전역·학습·그래프 코드 제외, `ORIGINAL`은 우리 38열 목록을 주입하고 노트북 열 순서와 같음을 확인) **실데이터 Fold 0**의 학습/검증 행으로 실행하고, 우리 포팅의 75열 특징 프레임과 원핫 행렬, 가중치가 **비트 동일**(열 이름·순서·dtype·값)임을 확인한다. 이 대조는 동결 환경에서 두 구현의 일치만 보증한다.
2. **입력 점검**: Fold 크기·서로소, 지역 ID 정수 왕복, 이진 열 0/1, 홀드아웃 경로 가드.
3. **행렬 점검**: Fold 0의 75열 순서, 원핫 열 수, 검증 행렬 열 = 학습 행렬 열, 수치 결측 0, 미관측 지역·범주 건수.
4. **라벨 탐침(학습 없음)**: Fold 0 검증 행에 실제 라벨을 붙여 섞어도 검증 행렬이 바뀌지 않음(비트 동일)을 확인한다.
5. **모델 프로브(합성 400행, 예산 밖)**: L·X 설정을 작은 트리 수로 학습해 저장·재로딩 확률 차이와 동일 입력 재학습의 결정성을 확인한다.
6. **비교군 점검**: 비교군 OOF의 SHA, 행 정렬, 정답 라벨, 등록된 CV 평균·Recall3·3→1 재계산 일치.

## 6. 지표와 사전 고정 기술 판정

보고 지표(팔별 Fold별·평균·풀링): Macro F1(labels [1,2,3]), 평균·SD(ddof=1), Accuracy, 등급별 P/R/F1, 혼동행렬, Recall3, 3→1·3→2 건수·비율(분모 실제 3등급 69,774), 예측 비율, 비교군 대비 turnover. age 995 집단과 geo1 26/20/13은 관찰 항목으로 둔다.

| 판정 | 규칙 (모두 같은 Fold의 Fold 단위 ΔMacro F1) | 라벨 |
|---|---|---|
| **D1** 비교군별 (팔 L·X × 비교군 T33_E1·T33_E2·T14·T8_N·LR_C·T0) | 평균 Δ ≥ +0.005 그리고 4/5 Fold 이상 팔이 큼 → `ADVANTAGE_DESCRIPTIVE`; 평균 Δ ≤ −0.005 그리고 4/5 Fold 이상 작음 → `DISADVANTAGE_DESCRIPTIVE`; 그 외 `INDISTINGUISHABLE`. LGBM-O는 참고(`REFERENCE_ONLY`). | 기술 라벨, 채택 아님 |
| **D2** 안전 지표 | 풀링 Recall3, 3→1·3→2 건수·비율을 비교군 옆에 병기, 판정 없음. 3→1 허용 상한은 정하지 않는다(T29 사용자 결정). | 없음 |
| **D3** L 대 X | Δ = L − X. 평균 Δ ≥ +0.003 그리고 4/5 Fold 이상 L이 큼 → `LGBM_AHEAD_DESCRIPTIVE`; 평균 Δ ≤ −0.003 그리고 4/5 Fold 이상 X가 큼 → `XGB_AHEAD_DESCRIPTIVE`; 그 외 `SIMILAR`. 노트북 단일 검증 분할의 차이(0.0014)가 5개 Fold에서 유지되는지 기술한다. | 기술 라벨 |
| **D4** 노트북 값과의 거리 (참고) | L CV 평균과 노트북 테스트 0.7131의 \|차\| ≤ 0.005 `NEAR`, ≤ 0.015 `MODERATE`, 그 밖 `FAR`. L 대 노트북 검증 0.7091, X 대 노트북 검증 0.7077은 숫자만. "재현 성공/실패"로 부르지 않는다. | 참고 라벨 |

- 대표 줄은 L(노트북 최종 모델)이다. 모든 수치를 라벨과 무관하게 보고한다. 홀드아웃 평가·최종 모델 교체·채택 판정은 하지 않는다.
- 비교군 등록값: T33_E1 0.707285 / Recall3 0.667283 / 3→1 782, T33_E2 0.706832 / 0.666910 / 779, T14 0.700427 / 0.673016 / 744, T8_N 0.699342 / 0.647648 / 530, LR_C 0.688687 / 0.639794 / 452, T0 0.683677 / 0.638433 / 467, LGBM_O 0.669847 / 0.590077 / 303. 이 비교는 여러 요소가 동시에 다른 파이프라인 간 기술 비교이며 한 요소 비교가 아니다.

## 7. 해석 원칙과 한계

1. 노트북 테스트 0.7131과 우리 CV 평균은 같은 양이 아니다(분할·행 구성·학습 크기·환경·단일 분할 대 5-Fold 평균). 차이는 요인을 나열만 하고 분리하지 않는다.
2. **정보 유입**: 노트북 설정은 전체 260,601행의 무작위 분할에서 골랐고, 그 행들은 우리 개발 Fold 검증 행과 과거 홀드아웃 행과도 겹쳤을 가능성이 높다(구성원 일치는 확인하지 않음, 홀드아웃 접근 금지). 구판에서 테스트를 보고 내린 결정도 이어져 있다. 따라서 이 벤치마크 점수와, 이 파이프라인을 이후 최종 평가에 올린 결과는 모두 독립 성능이 아니다.
3. 우리 5-Fold는 이미 수십 개 설정 비교에 반복 사용됐다(선택 통계). Fold 5개는 독립 표본이 아니라서 승수·SD를 유의성으로 읽지 않는다.
4. 층화 분할은 같은 지역이 학습·검증에 모두 나온다. 지역 피해 비율 변수는 처음 보는 지역에서 다르게 동작할 수 있으며, geo2/geo1 일반화는 평가하지 않는다.
5. L과 X는 노트북에서 후보 수(각 3개)와 손으로 다듬은 정도가 같지만, 다른 모델 계열과의 공정 비교는 이 실험 범위 밖이다. 파생변수 효과는 37개 묶음 단위로만 다뤄졌고 이 실험도 분해하지 않는다.
6. 3→1 같은 중대 오류는 Macro F1에 반영되지 않는다. 가중치 0.5는 1등급 예측을 늘려 3→1을 늘릴 수 있으며, 이는 결과가 아니라 예상이고 관찰로만 기록한다.

## 8. 독립 감사 (공개 보고 전 필수)

학습 담당과 다른 주체가 새 fit·pickle 역직렬화·실행기 import 없이 수행한다. ① 산출물 SHA·원장·`attempts.jsonl` 대조, 학습 횟수 ≤ 상한, 완료 unit 재학습 0, 홀드아웃 접근 0 ② Fold 학습/검증 서로소와 union = 개발 전체 ③ 저장 모델 파일로 확률 재추론(L ≤ 1e-12, X ≤ 1e-6, 라벨 일치) ④ 별도 구현으로 Fold별 검증 행렬을 원시 개발 자료와 학습 Fold에서 다시 계산해 저장 행렬과 대조(학습 행렬은 SHA 대조) ⑤ OOF에서 지표·비교군 값·판정 라벨 독립 재계산 ⑥ 공개 보고 초안이 팀원 코드 원문·행별 예측을 싣지 않았는지 검토.

## 9. 공개 범위·경계

- 공개(감사 PASS 뒤): 집계 지표, Fold별 Macro F1, 판정 라벨, 한계, 파이프라인 구성 수준 요약. 비공개: 노트북 원문·셀 소스·추출본, 행별 예측·OOF, 모델, 특징 행렬, manifest.
- 우리 실행기는 출처와 노트북 SHA를 파일 머리에 표기하고 노트북 주석 문장을 복사하지 않는다(T33과 같은 방식).
- 홀드아웃은 읽지 않는다. 원시 전체 CSV(260,601행, 홀드아웃 포함)는 쓰지 않는다. 기존 브랜치·기존 비공개 결과 변경 금지. push는 독립 감사 뒤 메인이 한다.
