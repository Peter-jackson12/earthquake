# 지진 피해 분류: 논문 벤치마크와 적용 아이디어

> 2026-10-13 작성. 논문에서 확인한 접근과 우리 프로젝트에 적용할 제안을 구분한다. 개인 검토 메모이며 팀의 확정 결정이나 새 실험 완료 보고가 아니다.

## 작업 경계

- 기존 `preprocess.py` v1.0.1, 공통 Baseline, 저장된 개발 데이터와 fold를 보존한다.
- [현재 계획](PLAN.md), [실행 안내](RUNBOOK.md), 기존 reports의 결과를 먼저 확인한다. 이미 수행한 실험·오류 분석을 다시 만드는 대신 부족한 부분만 제안한다.
- 여기서 설명하는 추가 비교는 아직 실행하지 않았다. 최종 홀드아웃 평가나 전처리 재생성을 요청하는 문서가 아니다.
- 원본 행·개별 예측·모델은 공개 저장소에 추가하지 않는다. 확인된 집계와 근거만 기록한다.
- 주지표는 labels=[1,2,3]의 Macro F1이다. 논문 점수와 우리 점수는 데이터·등급·분할·집계 방식이 같다고 검증되지 않으면 직접 우열 비교하지 않는다.

## 1. 피해를 낮게 예측한 오류를 구분하기

**논문에서 확인:** Ghimire 등의 [지역 규모 지진 피해 예측 연구](https://doi.org/10.1177/87552930221106495)는 피해 등급의 순서와 혼동행렬을 고려해 오류를 해석한다.

**우리 적용 제안:** 실제 3등급을 2등급으로 예측한 경우와 1등급으로 예측한 경우를 분리한다. 3→2와 3→1은 우리의 3등급 과제에 맞춘 표현이며 논문의 등급 체계를 그대로 옮긴 것이 아니다.

- 각 오류의 건수와 비율을 함께 보고한다.
- 두 비율의 분모는 동일 평가 데이터의 **실제 3등급 건수**로 통일한다.
- `3→2 비율 = 실제 3·예측 2 건수 / 실제 3등급 전체 건수`.
- `3→1 비율 = 실제 3·예측 1 건수 / 실제 3등급 전체 건수`.
- 3등급 Recall과 함께 해석하고, 실제 3등급이 0건인 평가 단위는 비율을 계산할 수 없다고 명시한다.
- 기존 혼동행렬이 있으면 모델 재학습 없이 산출 가능한지 먼저 확인한다.
- 임의의 오류 비용을 실제 금전 피해로 바꾸거나, 분류 결과를 건물 안전의 확정 판정으로 사용하지 않는다.

## 2. 불균형 처리의 이득과 손해를 함께 보기

**논문에서 확인:** Ghimire 연구의 등급별 Recall 검토와 [FAITH 논문](https://faith.futuretechsci.org/index.php/FAITH/article/view/109)의 불균형 처리 방법 비교를 참고한다. FAITH의 수치 자체를 재현 목표로 가져오지는 않는다.

**우리 적용 제안:** 같은 fold에서 처리 전후 Macro F1과 등급별 Precision·Recall·F1을 비교한다.

- 소수인 1등급의 Recall이 좋아져도 3등급 Recall이나 전체 Macro F1이 악화될 수 있다. 개선 항목만 선별해 제시하지 않는다.
- 가중치와 샘플링을 동시에 바꾸기보다 한 요소씩 비교한다.
- 샘플링은 각 학습 fold에서만 수행하고 검증 분포는 그대로 둔다.
- 처리 후 등급별 건수·가중치·방법을 기록한다.
- 현재 진행한 가중치 실험이 있으면 먼저 재사용하고, RUS·SMOTE 계열 등 아직 없는 비교를 후속 후보로 둔다.
- 불균형 처리가 항상 성능을 높인다는 결론을 미리 정하지 않는다.

## 3. 변수 묶음의 기여를 별도 실험으로 확인하기

**논문에서 확인:** Ghimire의 전체 입력과 축소 입력 비교 접근을 참고한다.

**우리 적용 제안:** 전체 입력 Baseline을 유지하고 지역 정보 등 한 묶음만 제외한 별도 설정을 같은 fold에서 비교한다. **지역 변수 제거는 우리 실험 제안이지, 논문이 동일 실험을 했다는 주장이 아니다.**

- 원본 입력이나 전처리 파일을 직접 삭제·덮어쓰지 않는다.
- 한 번에 하나의 변수 묶음만 바꾸고 모델 설정·평가 행·seed를 고정한다.
- Macro F1뿐 아니라 1·2·3등급 지표와 계산량을 함께 비교한다.
- 성능 차이를 인과효과로 해석하지 않는다.
- 지역 변수를 뺀 실험만으로 새로운 지역에서 일반화된다고 주장할 수 없다. 지역 단위 분리 평가는 별도 설계이며 우선순위 합의가 필요하다.
- 필수 불균형 비교·튜닝·제출물을 먼저 확보하고 수행 여부를 정한다.

## 4. 모델 비교표에 안정성과 계산량 넣기

**논문에서 확인:** [ACK 2023 논문](https://koreascience.kr/article/CFKO202333854980394.pdf)의 CV 평균·표준편차 표현, Ghimire 연구의 계산비용을 고려한 모델 선택을 참고한다.

**우리 적용 제안:** 다음 항목을 같은 표 또는 연결된 집계로 관리한다. Macro F1과 등급별 항목은 우리 과제에 맞춘 구성이다.

| 항목 | 기록 기준 |
|---|---|
| 모델·실험명 | Baseline인지 가중치/샘플링/변수 변경인지 구분 |
| 데이터·fold | 데이터 버전, 평가 범위, 저장된 fold 동일 여부 |
| Macro F1 CV 평균·표준편차 | fold별 Macro F1의 집계. 표준편차를 신뢰구간으로 부르지 않음 |
| OOF Macro F1 | 전체 OOF에서 계산한 값. fold 평균과 별도 표시 |
| 등급별 Precision·Recall·F1 | 평균 방식 없이 각 등급별 값과 표본 수 기록 |
| 3→2·3→1 오류 | 실제 3등급을 분모로 한 비율과 건수 |
| 학습시간 | 같은 장비·병렬화·데이터 범위에서 비교 |
| 경고·제약 | 수렴 경고, 메모리 한계, 표본 실행 여부 등 |

- 표본 실행과 개발 전체 CV를 같은 조건의 성능처럼 섞지 않는다.
- 기존 집계 파일에서 만들 수 있는 열부터 활용한다.
- 최고 점수만으로 자동 선정하지 않고 오류 특성·계산량·재현 가능성을 함께 검토한다.
- 빈 칸을 예시 숫자로 채우지 않는다.

이러한 차이는 참고자료를 배제할 이유가 아니라 **방법을 참고하는 것과 같은 조건의 성능을 비교하는 것을 구분해야 하는 이유**다.

## 다음 확인 순서

1. 기존 Baseline·후속 실험 보고서에 이미 있는 지표와 오류 집계를 확인한다.
2. 추가 학습 없이 만들 수 있는 오류표·비교표부터 정리한다.
3. 아직 없는 비교만 팀에 제안하고 실행 범위·평가 조건을 합의한다.
4. 실제로 실행한 뒤 근거 파일과 함께 결과를 기록한다.
5. 개인 브랜치의 문서를 검토한 후 필요한 부분만 팀 통합 절차에 따른다.
