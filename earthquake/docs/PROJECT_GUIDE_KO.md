## 2. 문제와 데이터 — 주제 가이드 기준

건물의 위치·구조·재료 특성으로 2015년 네팔 지진의 관측 피해 등급 1·2·3을 분류한다. 전처리와 클래스 불균형 처리의 효과 및 부작용을 비교하고, 건물 취약성 이해와 점검 우선순위 검토에 필요한 한계를 설명하는 학습 프로젝트다.

- 분석 단위: 건물 한 채.
- 가이드상 데이터: 260,601행 × 40열 = 건물 식별자 1개 + 입력 후보 38개 + 정답 1개.
- 정답: `damage_grade`. 순서가 있는 등급이지만 이번 과제는 다중 분류로 다룬다.
- 가이드상 분포: 1등급 25,124건, 2등급 148,259건, 3등급 87,218건.
- 1등급은 상대적으로 낮은 피해이지 반드시 무피해가 아니다. 3등급도 모든 사례가 완전히 붕괴했다는 의미로 단정하지 않는다.
- `building_id`는 결합·추적용이며 모델 입력에서 제외한다.
- `geo_level_*_id`는 지역 코드다. 숫자의 크기를 물리적 거리나 순위로 해석하지 않는다.
- `area_percentage`, `height_percentage`를 실제 제곱미터·미터로 표현하지 않는다.
- 가이드상 결측·전체 행 중복이 0이어도 실제 사용하는 파일에서 다시 확인한다. 위 수치는 가이드 설명이며 이 문서 작성 과정에서 원본 전체를 재검증한 결과가 아니다.

출처 확인: [DrivenData 데이터 안내](https://www.drivendata.org/competitions/57/nepal-earthquake/page/136/) 및 [다운로드 페이지](https://www.drivendata.org/competitions/57/nepal-earthquake/data/). 다운로드에는 로그인이 필요할 수 있다. 팀이 받은 파일의 출처·버전·해시를 별도로 맞추고, 원본 CSV의 공개 재배포 가능 여부를 확인하기 전에는 저장소에 올리지 않는다.

**원문 정리 주의:** 주제 문서 일부에 `current_energy_efficiency`, 에너지 등급 등 다른 주제의 표현이 남아 있다. 지진 데이터의 실제 컬럼과 `damage_grade`를 기준으로 검토하며 존재하지 않는 컬럼을 전처리 요구사항으로 만들지 않는다.

## 3. 필수 실험과 평가

| 항목 | 수행 내용 |
| --- | --- |
| 문제 정의·EDA | 예측 대상과 사용 맥락, 중요한 오류, 변수 유형·품질·등급 분포를 설명 |
| 공통 분할 | 층화 분할과 동일한 평가 기준으로 네 모델 비교. 분할 ID·seed·CV 방식을 기록 |
| Baseline | 필요한 기본 전처리 후 불균형 처리 전 성능 확보 |
| 필수 네 모델 | Logistic Regression, Decision Tree, Random Forest, **sklearn GradientBoostingClassifier** |
| 불균형 처리 | 클래스 가중치, Random Under Sampling, SMOTE 계열의 효과와 적용 근거 비교 |
| CV·튜닝 | CV 방식, 탐색 범위, 선택한 파라미터와 검증 결과 기록 |
| 주지표 | **Macro F1**. Accuracy와 등급별 Precision·Recall·F1·표본 수도 함께 보고 |
| 오류 분석 | 혼동행렬로 개선·악화된 등급 및 피해 과소/과대 예측을 해석 |
| 최종 선택 | 검증 결과와 목적을 근거로 선택한 후 분리해 둔 Test에서 최종 평가 |
| 대시보드 | 실제 EDA·모델별 성능·처리 전후·최종 평가 결과를 Streamlit으로 표현 |

- XGBoost/LightGBM 등 추가 모델을 쓰더라도 필수 GradientBoostingClassifier를 대체한 것으로 보지 않는다.
- 1등급은 가장 적지만, 심각한 피해인 3등급을 낮게 예측하는 오류도 중요하다. 소수 클래스와 업무상 중요한 클래스를 구분한다.
- GradientBoostingClassifier에는 `class_weight`가 없으므로 해당 가중치 실험은 학습용 `sample_weight`로 설계한다.
- 범주와 수치가 섞여 있으므로 일반 SMOTE의 보간이 타당한지 검토한다. SMOTENC 적용 가능성, 인코딩과 샘플링 순서, 이웃 수, 처리 후 등급별 건수를 기록한다.
- 로지스틱 회귀는 스케일링뿐 아니라 수렴 경고·반복 횟수도 확인한다.

## 4. 누수 방지와 비교 원칙

1. 최종 평가 데이터를 먼저 분리하고 모델·전처리·튜닝 선택에 사용하지 않는다.
2. 대체값·인코더·스케일러처럼 데이터에서 학습하는 변환은 **각 CV 학습 fold에서만 fit**한다.
3. 샘플링도 학습 fold 내부에서만 수행한다. 검증·최종 평가 분포는 변경하지 않는다.
4. ID·정답·예측 시점에 알 수 없는 정보를 입력에 넣지 않는다.
5. Baseline과 변경 실험의 평가 행·지표·평균 방식을 맞춘다. 전처리·가중치·샘플링을 동시에 바꾸었다면 개선 원인을 하나로 단정하지 않는다.
6. 가능한 한 변경 요소를 분리하여 Macro F1 변화와 등급별 손익을 함께 기록한다.
7. 합성 데이터 호환성 테스트, 코드 검토, 원본 데이터 실행 보고, 독립 재실행, 실제 성능 결과를 구분한다. AI 예시 숫자를 실험 결과로 제출하지 않는다.

## 5. 기존 전처리 작업을 이어받는 방법 — 중복 작업 방지

**기존에 진행한 전처리 산출물을 출발점으로 사용한다. 이 가이드 추가는 새로운 전처리 구현이나 재실행 요청이 아니다.**

- 진행 중인 전처리 작업의 **최신 코드·README·실행 보고서**를 먼저 인계받는다. 오래된 첨부본을 임의로 다시 올리거나 별도 전처리 모듈을 새로 만들지 않는다.
- 버전 또는 커밋, 파일 해시, 원본 데이터 해시, 실행 환경, 분할 ID와 seed를 맞춘다. 수정 중인 버전이 있으면 완료된 인계본 기준으로 통합한다.
- 기존 분할·전처리의 설계 이유와 실제 보고서를 읽고, 필요한 추가 검증·실험만 수행한다.
- 이미 실행된 결과는 조건·코드·데이터를 확인하여 재사용한다. 재실행은 버전 변경, 재현성 검증 등 이유가 있을 때 기록하고 수행한다.
- 개인 구현의 80/20 분할, seed 42, 5-fold 등의 설정을 팀의 확정 합의로 간주하지 않는다. 공식 요구사항을 충족하는지 검토한 뒤 팀 공통 기준을 정한다.
- 사전 합성 데이터 테스트가 통과했더라도 원본 데이터에서 네 모델 학습·CV·튜닝·성능 평가까지 완료되었다고 적지 않는다.
- 담당자가 개선 중인 부분은 병렬로 중복 수정하지 않는다. 이슈나 팀 작업표에서 작업 대상·담당·산출물·완료 조건을 확인한다.

이 문서를 추가하기 직전 저장소는 README 제목만 있는 상태였으며, 전처리 코드의 저장소 반영과 최신 인계 버전은 별도 확인 대상이었다. 이후 실제 반영 상태는 저장소 이력과 해당 코드 문서를 기준으로 판단한다.

## 6. 팀이 함께 정할 항목 — 아직 확정된 결정 아님

- 문제 정의 한 문장, 주요 사용자·활용 맥락, 중요한 오분류.
- 공통 데이터 버전, 분할 방법·평가 ID, seed, CV 수, 실험 시간·메모리 예산.
- 네 모델 Baseline과 불균형 처리 비교 범위, 필수 항목부터 끝내는 우선순위.
- 각자의 공통 분석·모델링 수행과 별도로 맡을 통합·검토·대시보드·문서 주 담당.
- 브랜치/PR 검토·병합 방식, 충돌 방지를 위한 파일 담당, 결과 저장 규칙.
- 개인 기록·팀 Notion 업데이트 시점과 최종 제출 책임자.

권장 순서는 문제·데이터 이해 → 기존 전처리 인계와 Baseline → 불균형 처리·튜닝 → 공정한 비교와 최종 선택 → 대시보드·README·발표 정리다. 초반부터 모든 역할을 고정할 필요는 없지만 데이터·평가 기준·다음 공유 시점은 먼저 맞춘다.

## 7. 범위 관리와 최종 체크

- [ ] 문제 정의와 중요한 오류를 팀이 합의했다.
- [ ] 기존 전처리의 최신 인계본과 공통 분할을 확인했다.
- [ ] 네 필수 모델 Baseline·CV·튜닝·불균형 처리 비교 근거가 있다.
- [ ] Macro F1뿐 아니라 등급별 지표와 혼동행렬, 악화된 부분도 설명했다.
- [ ] 최종 평가 데이터가 선택·튜닝에 사용되지 않았다.
- [ ] Streamlit 수치가 실제 저장된 결과와 일치하고 README의 실행 절차가 확인되었다.
- [ ] 팀원별 수행·문제 해결 기록과 팀 의사결정이 정리되었다.
- [ ] 제출할 모든 결과가 Public 저장소 main에 있고 LMS 제출 항목을 확인했다.

SHAP, 추가 피처, 의사결정 임계값, 지역 단위 일반화 비교는 필수 완료 후 검토할 심화 항목이다. 대시보드는 결과 설명이 목적이며 실시간 예측 서비스나 접속 때마다 재학습하는 기능은 필수가 아니다. 이 데이터만으로 미래 지진의 발생이나 모든 지역의 실제 건물 안전을 보장한다고 주장하지 않는다.
