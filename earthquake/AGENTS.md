# 작업 목표와 경계

목표: 팀 공통 `main`에는 검증된 전처리와 평가 계약·제출 문서를 두고, 개인 연구·모델링 실험은 각 개인 브랜치에서 수행·검토 후 필요한 항목만 PR로 통합한다.

- `preprocess.py`는 v1.0.1을 보존한다. 변경이 필요하면 결함 재현·회귀 테스트·버전 기록을 먼저 남긴다.
- 모델링은 `load_development()`와 저장된 fold만 사용한다. 전체 데이터에 인코더/스케일러를 fit하지 않는다.
- 주지표는 labels=[1,2,3]의 Macro F1이다. 클래스별 Precision/Recall/F1과 혼동행렬도 남긴다.
- 테스트·튜닝·early stopping에 홀드아웃을 사용하지 않는다. 최종 후보와 평가 계획을 사용자가 확정하기 전에는 최종 평가를 실행하지 않는다.
- 원본 38개 입력과 특수값을 임의 삭제하지 않는다. 개선은 기존 기준선과 한 요소씩 비교한다.
- 새 실험은 개인 브랜치와 새 출력 경로를 사용한다. 개인 브랜치의 성능·보고서를 곧바로 팀 공통 결과로 기록하지 않는다. 팀의 검토와 합의 후에만 PR로 `main`에 반영한다.
- 원시 데이터/행별 예측/모델/자격증명은 공개 Git에 올리지 않는다. 집계 파일만 검토 후 reports/에 넣는다.
- `python -m unittest discover -s tests -v`를 실행하고 pass/skip을 구분한다. 표본 CV와 전체 CV도 명확히 구분한다.
- 학습 병렬화는 한 단계에서만 제한적으로 사용한다. 희소 행렬을 전체 `.toarray()`로 변환하지 않는다.
- 저장소 권한·공개 여부·팀원 배정·Slack/Notion 게시를 임의 변경하지 않는다.
- 팀 공통 진행 상태는 `docs/PLAN.md`, 개인 실험의 결과와 로그는 해당 브랜치의 `reports/`에 기록한다. 이 문서는 예약 실행이나 백그라운드 서비스를 설정하지 않는다.
