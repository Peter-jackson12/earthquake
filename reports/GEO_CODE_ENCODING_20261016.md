**읽는 법과 반올림.** 성능 지표·Δ·비율은 소수 6자리로 반올림했다. 시간(초)과 메모리(MiB)는 표시 편의상 소수 3자리로 줄였고 6자리 값은 JSON에 있다. 원자료 전체 자릿수는 비공개 `analysis.json`에 있다. 반올림 때문에 표시한 Δ와 평균의 합이 1e-6 단위로 어긋날 수 있다. Δ = 후보 − 기준(같은 Fold), SD는 ddof=1이다. "Fold 평균"은 5개 Fold Macro F1의 평균, "pooled"는 208,480건을 한 번씩 예측한 OOF를 합친 값이며 서로 다른 요약이다. 3→1·3→2의 분모는 실제 3등급 69,774건이다. 같은 Fold를 여러 번 쓴 비교이므로 Fold와 풀링 값 모두 독립 표본이 아니며 p-value·신뢰구간·인과 효과를 주장하지 않는다. 정수 건수는 반올림하지 않는다. **반올림 예외**(유효숫자를 보존하려고, 6자리로 반올림하면 0이 되거나 자릿수를 잃는 값을 JSON에는 유효숫자 4자리 문자열로 적었다): 대조 RF_OH의 최대 확률 절대 차(3.331e-16), LR 2차 대조 확률 허용치(1e-06), 감사의 LR 기울기 최대값(9.974e-05). 판정 규칙의 경계 허용 오차(1e-12)와 1e-9·2e-9 등 규칙 상수는 본문 문장에만 적었다. 열 머리나 문장에 "사전등록 판정 아님"이 붙은 값, JSON에서 접미사 `_auxiliary_not_a_preregistered_verdict`가 붙은 필드는 보조 관찰이다. 사전등록 판정에 쓰인 것은 §3의 성능 태그(Fold 평균 Δ, 후보 승 Fold 수, ΔRecall3)와 계산량 태그(Fold 비율 중앙값)뿐이다.

### 2.1 한 요소 정의

바꾼 것은 `geo_level_1_id`, `geo_level_2_id`, `geo_level_3_id` 세 열의 표현뿐이다. 입력 38열 전부, 특수값(age 995·0), 저장 Fold, 분류기 하이퍼파라미터·`random_state`, 결정 규칙(확률 argmax)은 모든 팔에서 같고 가중치·재표집·임계값 조정·early stopping·튜닝은 없다. 하이퍼파라미터는 원핫에서 정해진 기존 값 그대로이며 `NUM`/`NAT`에 맞춰 다시 조정하지 않았다.

| 표현 | 정의 |
|---|---|
| `OH` 범주형(원핫) | v1.0.1 `OneHotEncoder(handle_unknown='ignore', sparse_output=True, float32)`. 학습 Fold 값만 어휘로 쓰고 미관측은 전부 0 |

## 3. 사전등록 비교

규칙(계획 §9): 성능 태그는 Fold 평균 Δ, Fold 승수(5개 중 후보가 엄격히 큰 Fold 수), 3등급 Recall 변화로 정한다. `NUM_HIGHER` = Δ ≥ +0.003 그리고 승수 ≥ 4 그리고 ΔRecall3 ≥ −0.01, `NUM_LOWER` = Δ ≤ −0.003 그리고 승수 ≤ 1, `NO_MATERIAL_DIFFERENCE` = |Δ| < 0.003, `MIXED` = 나머지. `SAFETY_3to1`은 두 팔 중 3→1 건수가 상대 +10% 넘게 그리고 절대 +30건 이상 많은 팔에 양방향으로 표시한다. 계산량 태그는 5개 Fold 비율(후보/기준)의 중앙값이 0.5 이하면 `LOWER`, 2.0 이상이면 `HIGHER`, 그 사이면 `SIMILAR`이고 Fold별 비율이 서로 다른 구간에 걸치면 `BOUNDARY`를 병기한다. 이 태그들은 5 Fold의 기술 판정이며 유의성 검정이 아니고 "수치 표현이 더 낫다/원핫이 낫다"는 추천이 아니다.

### 3.3 계산량 보조 사실 (사전등록 판정 아님)

- 열 수: 원핫 팔은 Fold마다 12,541~12,624열이고 `NUM` 팔은 LR 69열, DT·GBC·RF 68열, LGBM 39열이다. `LGBM_NAT`도 39열(dense)이다.
- 학습 행렬 저장 크기는 CSR에서 거의 같다(비율 0.999~1.000). 원핫의 지역 3블록도 행당 비영 3개이고 `NUM`의 지역 3열도 행당 비영 3개이므로 nnz가 거의 같다. 열 수는 크게 줄었지만 저장 크기 차이는 나타나지 않았다.
- `LGBM_NAT`(dense 39열)은 `LGBM_OH`(CSR)보다 예측 시간 비율이 2.959304 중앙값, 모델 파일 크기 비율이 4.578101 중앙값으로 관측됐다. 컨테이너가 다르므로 표현 차이로 읽지 않는다.
- 모델 파일 크기 비율이 `HIGHER`인 것은 `RF_NUM`(2.191561; 트리 노드 수 Fold 평균 1,143,422 대 518,330)이고, 예측 시간 비율이 `HIGHER`인 것은 `GBC_NUM`(2.131873), 학습 시간 비율이 `HIGHER`인 것은 `DT_NUM`(2.569633)이다. `LR_NUM`은 학습 시간(0.182588; noisy 쌍 포함 값)과 모델 파일 크기(0.032252; 결정적 값)가 `LOWER`이고 `n_iter`는 120~144로 `LR_OH`(566~595)보다 적었다(§4의 오염 경고 적용).

### 3.4 `finalize` 요약 라벨과 null의 의미

`finalize`가 `analysis.json`에 기록한 7개 비교의 성능 태그는 다음과 같다.

| 비교 | `performance_tag` | `container_confounded` | 계산량 태그 |
|---|---|---|---|
| LR: `LR_NUM` vs `LR_OH` | `NUM_LOWER` | false | 부여 |
| DT: `DT_NUM` vs `DT_OH` | `NUM_HIGHER` | false | 부여 |
| GBC: `GBC_NUM` vs `GBC_OH` | `NUM_LOWER` | false | 부여 |
| RF: `RF_NUM` vs `RF_OH` | `NUM_LOWER` | false | 부여 |
| LGBM: `LGBM_NUM` vs `LGBM_OH` | `NUM_LOWER` | false | 부여 |
| LGBM: `LGBM_NUM` vs `LGBM_NAT` | `NUM_LOWER` | true | 없음 (컨테이너 섞임) |
| LGBM: `LGBM_NAT` vs `LGBM_OH` | null | true | 없음 (컨테이너 섞임) |

- LR `NUM_LOWER`, DT `NUM_HIGHER`, GBC `NUM_LOWER`, RF `NUM_LOWER`, LGBM `NUM_LOWER`(`LGBM_NUM` vs `LGBM_OH`), `LGBM_NUM` vs `LGBM_NAT` `NUM_LOWER`, `LGBM_NAT` vs `LGBM_OH` **null**.
- **null의 의미.** 성능 태그 어휘(`NUM_HIGHER`/`NUM_LOWER`/…)는 `NUM` 후보를 기준 팔과 비교할 때만 사전등록돼 있다(계획 §9.1 "Δ = `NUM` − 기준"). `LGBM_NAT` vs `LGBM_OH`는 계획 §5가 "기존 짝 재확인"으로 둔 보조 비교라 태그를 정의하지 않았고 실행기도 이 쌍에 `performance_tag`를 부여하지 않았다(null). null은 "차이 없음"(`NO_MATERIAL_DIFFERENCE`)이나 판정 보류가 아니라 **태그가 정의되지 않았다**는 뜻이다. 값 자체는 보고한다: Δ 평균 +0.029375, 후보 승 5/5 Fold, ΔRecall3 +0.057299, 3→1 530 대 300. 입력 평균은 기존 보고와 같다(`LGBM_NAT` 평균 0.699342 = T8 N, `LGBM_OH` 평균 0.669966 = T9 P). 기존 T8/T9 보고의 짝 차이 +0.029376은 6자리로 반올림한 두 평균끼리 뺀 값이고, 이 보고서의 +0.029375는 반올림 전 평균의 차이를 6자리로 반올림한 값이라 마지막 자리가 1e-6 다르다.
- 같은 이유로 `container_confounded=true`인 두 비교(`LGBM_NUM`(CSR) vs `LGBM_NAT`(dense), `LGBM_NAT`(dense) vs `LGBM_OH`(CSR))에는 계산량 태그를 붙이지 않았다. `LGBM_NUM` vs `LGBM_NAT`의 성능 태그 `NUM_LOWER`는 계획 §5가 둔 보조 비교의 성능 쪽 규칙을 적용한 것이다. 계산량 값(§3.2)은 컨테이너가 섞여 표현 비교로 읽지 않는다.

### 4.2 설계 규칙과 `analysis.json`의 실제 처리

- **설계 규칙(계획 §6.1)**: 유휴 CPU가 10% 이하가 아니면 최대 60초 대기 후 `noisy`로 **표시하고 진행**한다. "결과를 버리지 않고 표시"하는 것이 규칙이며 noisy fit을 계산량 판정에서 빼는 규칙은 없다. 측정 전용 예열 1회는 처음부터 폐기 대상이다.
- **`finalize` 처리**: 계산량 비율 계산(`compute_comparison`)은 noisy 플래그를 입력으로 받지 않는다. 학습·예측·종단 시간, 모델 파일 크기, 학습 행렬 저장 크기의 Fold 비율은 **noisy fit을 포함해 5개 Fold 전부**로 계산했고 중앙값에서 제외한 Fold는 없다. noisy 여부는 원장·`analysis.json`의 `ledger.noisy_fits`와 Fold 기록의 `noisy`에만 남아 있다.
- **`eligible_folds`는 noisy와 무관하다.** `memory_mib.eligible_folds`는 메모리 16 MiB 하한/`FLOOR_LIMITED` 규칙으로만 정해지며, 7개 비교 모두 `[]`(`n_eligible_folds=0`, 제외 Fold `[0,1,2,3,4]`)다. 즉 메모리 태그가 전부 부여되지 않은 것은 noisy와 무관하게 이 하한 규칙의 적용 결과다.
- noisy 쌍 포함 현황(후보 또는 기준 어느 한쪽이라도 noisy인 Fold). 감사 영수증의 `noisy_exposure_by_comparison`과 7개 비교 모두 일치한다:

| 비교 | noisy 포함 Fold 쌍 | 모두 noisy 없는 Fold 쌍 |
|---|---|---|
| LR: `LR_NUM` vs `LR_OH` | 0, 1, 2, 3, 4 (5/5) | 없음 (0/5) |
| DT: `DT_NUM` vs `DT_OH` | 없음 (0/5) | 0, 1, 2, 3, 4 (5/5) |
| GBC: `GBC_NUM` vs `GBC_OH` | 없음 (0/5) | 0, 1, 2, 3, 4 (5/5) |
| RF: `RF_NUM` vs `RF_OH` | 없음 (0/5) | 0, 1, 2, 3, 4 (5/5) |
| LGBM: `LGBM_NUM` vs `LGBM_OH` | 3, 4 (2/5) | 0, 1, 2 (3/5) |
| LGBM: `LGBM_NUM` vs `LGBM_NAT` | 3, 4 (2/5) | 0, 1, 2 (3/5) |
| LGBM: `LGBM_NAT` vs `LGBM_OH` | 3, 4 (2/5) | 0, 1, 2 (3/5) |

- DT·GBC·RF 비교 3건은 noisy 표시가 없어 알려진 오염은 없다(실행 중 경합은 fit 직전 유휴 검사로만 점검했고, 이 검사는 fit 도중 경합이 없었음을 보이지 못한다. DT 반복 측정의 학습 시간 변동계수 0.9~3.3%가 하한 참고다). **LR의 시간 비율(학습·예측·종단)은 5개 Fold 쌍 모두 noisy 포함이라 깨끗한 쌍이 없고**, 학습 `LOWER`·종단 `LOWER`·예측 `SIMILAR` 태그가 noisy 값에 기대고 있다. 모델 파일 크기(`LOWER`)·학습 행렬 저장 크기(`SIMILAR`) 비율은 결정적 값이라 해당하지 않는다. LGBM의 시간 비율은 Fold 3·4 쌍이 섞였다.

### 4.3 민감도 참고 (사전등록 판정 아님)

noisy 쌍을 뺀 Fold 0·1·2만으로 `LGBM_NUM` vs `LGBM_OH`의 비율 중앙값과 구간을 다시 계산한 참고 값이다. **"깨끗한 쌍"만 남기는 이 기준은 결과를 본 뒤 보고서 작성자가 정한 것**이며 사전등록 규칙이 아니다. 설계에 없는 사후 확인이고 태그를 바꾸지 않는다.

| 지표 | 5개 Fold 중앙값 (사전등록 태그) | Fold 0·1·2 중앙값 (참고 구간) | Fold 3·4 비율 |
|---|---|---|---|
| 학습 시간 | 0.440241 `LOWER` | 0.464970 `LOWER` | 0.425855 / 0.388509 |
| 예측 시간 | 0.726486 `SIMILAR` | 0.726486 `SIMILAR` | 0.720661 / 0.727012 |
| 종단 시간 | 0.509475 `SIMILAR` `BOUNDARY` | 0.528236 `SIMILAR` | 0.493919 / 0.458998 |
| 모델 파일 크기 | 0.865494 `SIMILAR` | 0.865572 `SIMILAR` | 0.864584 / 0.865494 |
| 학습 행렬 저장 크기 | 0.999045 `SIMILAR` | 0.999045 `SIMILAR` | 0.999038 / 0.999054 |

종단 시간의 `BOUNDARY`는 noisy Fold 3·4(0.493919/0.458998)에서만 생기고 깨끗한 Fold 0·1·2(0.509475/0.528236/0.558392)는 모두 0.5 초과이다(사후 확인, 태그 불변).

`LGBM_NUM` vs `LGBM_OH`는 깨끗한 쌍으로 좁혀도 구간이 바뀌지 않았다. 다만 이는 이 한 비교에 대한 확인이며, LR에는 깨끗한 쌍이 없어 같은 확인을 할 수 없다. noisy 상태의 `LR_OH`·`LR_NUM` 학습 시간이 깨끗한 환경의 값과 얼마나 다른지는 이 실행에서 알 수 없다. 모든 noisy fit의 학습 CPU/Wall 비는 위 표에서 0.951733 이상으로, fit 프로세스가 CPU를 거의 독점했음을 시사하지만 캐시·메모리 대역폭 경합까지 배제하지는 못한다.

### 4.4 F1 성능 판정에는 영향이 없다

- 성능 태그와 Δ·Recall3·3→1·3→2는 모두 저장된 OOF 예측에서 계산한다. 시간·CPU 상태는 입력이 아니다.
- 모든 분류기는 단일 스레드이고 `random_state`가 고정돼 있으며(LGBM은 `deterministic=true`), CPU 경합은 실행 시간을 바꿀 뿐 계산 결과를 바꾸지 않는다는 것이 설계 근거다(계획 §6.1).
- 실측 보강: noisy였던 `LR_OH` Fold 0의 예측은 같은 기계·venv의 이전 로컬 재적합과 확률 최대 차이 0.0, 등급 동일로 일치했다(2차 대조, §5). 시간과 무관하게 같은 결과가 재현됐다는 간접 증거다. 단 LGBM의 noisy Fold 3·4와 `LR_OH` Fold 1~4는 대조 대상이 아니다(대조는 Fold 0만).
- 감사 확인: noisy 14건을 포함한 55 fit 모두에서 저장 모델의 재추론 확률이 원 확률과 비트 동일(최대 절대차 0.0)이었고, 독립 재구성 행렬에서의 학습 Macro F1이 일치했으며, LR 수렴 fit의 저장 계수 기울기는 최대 9.974e-05(허용 2e-04)였다. 감사 기록의 CPU/Wall 비는 55 fit 중 최소 0.920177이고 감사 허용 상한 2.0을 넘은 fit은 없다. 이는 시간 경합이 결과의 일관성을 깨지 않았다는 확인이며, 시간 값이 깨끗한 환경의 값과 같다는 뜻은 아니다.
- 따라서 오염의 영향은 **계산량(시간) 비율에만** 해당한다. 모델 파일 크기·행렬 저장 크기·열 수·nnz는 시간과 무관한 결정적 값이고, 메모리 태그는 부여되지 않았다.

## 7. 결론

아래는 사전등록 규칙에 따른 라벨과 오류 프로파일의 기술 요약이며, 최종 모델 선정이나 확인적 결론이 아니다. 확인 평가(T29)는 현재 설계 초안만 있는 미승인 상태이며 승인 여부는 별도 사용자 결정이다.

**성능.**

1. 같은 모델에서 지역 3열을 정수 값 그대로 넣은 `NUM`은 5개 모델 중 4개에서 `NUM_LOWER`로 관측됐다: LR -0.217107, GBC -0.014831, RF -0.038370, LGBM -0.018945(`LGBM_OH` 대비). 네 비교 모두 후보 승 Fold가 0/5였고 Fold별 Δ가 전부 음수였다.
2. DT만 반대 방향으로 `NUM_HIGHER`(+0.020146, 5/5 Fold, ΔRecall3 +0.031115)였으나 `DT_NUM`의 3→1은 426건으로 `DT_OH`(165건)의 약 2.6배라 `SAFETY_3to1`이 함께 표시된다.
3. LR의 차이가 특히 크다: `LR_NUM` Fold 평균 0.471752, `LR_OH` 0.688860(Δ -0.217107), 3등급 Recall이 0.640067에서 0.196621로 내려갔다. 지역 열의 절대 계수 비중은 0.996745에서 0.010220으로 낮아졌다(기술 값이며 원인을 보이는 것이 아니다). T6R(0.4579, 지역 열 제거)은 참고 수치이며 설정이 달라 비교하지 않는다.
4. LGBM 세 지역 표현의 Fold 평균은 `LGBM_NAT` 0.699342, `LGBM_OH` 0.669966, `LGBM_NUM` 0.651022이다. `NUM`은 `NAT` 대비 -0.048320(`NUM_LOWER`, 0/5 Fold)로 관측됐고, `LGBM_NAT` − `LGBM_OH` 짝 차이는 +0.029375로 기존 T8/T9 값을 재확인했다(`performance_tag` null, §3.4). `LGBM_NAT`은 3→1이 530건으로 LGBM 세 팔 중 가장 많다.

**계산량(단일 스레드, 측정 오염 아래의 기술 값).**

5. 열 수는 원핫의 12,541~12,624열에서 `NUM`의 39~69열로 줄었다. 시간 비율은 모델마다 방향이 다르다(LR 전부·LGBM Fold 3·4 쌍의 시간 비율은 noisy 포함): 학습 시간은 `LR_NUM`·`LGBM_NUM`이 `LOWER`, `DT_NUM`이 `HIGHER`, `GBC_NUM`·`RF_NUM`이 `SIMILAR`였고, 모델 파일 크기는 `LR_NUM`이 `LOWER`, `RF_NUM`이 `HIGHER`, 나머지가 `SIMILAR`, 예측 시간은 `GBC_NUM`만 `HIGHER`였다. CSR 학습 행렬 저장 크기는 모든 `NUM`/`OH` 쌍에서 `SIMILAR`(비율 약 1.0)였다.
6. 메모리는 16 MiB 하한/`FLOOR_LIMITED` 규칙에 따라 7개 비교 모두 태그를 붙이지 못해 계산량의 메모리 축은 비어 있다(값만 §3.2).
7. 성능 축과 계산량 축을 나란히 보면 `LR_NUM`은 시간(noisy 포함 값)·모델 크기가 낮은 쪽이면서 성능도 크게 낮게 관측됐고, `DT_NUM`은 학습 시간이 높은 쪽이면서 성능이 높게 관측됐다. 이를 "수치가 낫다/원핫이 낫다"의 추천으로 읽지 않는다.

**하지 않은 주장.** 최종 모델 선정, 팔 간 우열의 확정, 모델 간 순위, 채택 권고를 하지 않는다. 이 결과는 새 독립 성능이 아니며 홀드아웃은 접근하지 않았다. 확인 평가(T29)는 현재 설계 초안만 있는 미승인 상태다. 지역 코드의 숫자 크기에는 의미가 없다는 것이 가이드의 전제이고, `NUM`은 "의미 있는 거리"가 아니라 임의 순서의 정수 축을 모델이 어떻게 쓰는지 보는 대조군이다. `DT_NUM`이 높게 관측된 것을 "정수 크기에 의미가 있다"는 근거로 읽지 않는다: 층화 CV에서는 같은 지역이 학습과 검증에 함께 있어 정수 축 분할이 지역 식별로 작동해도 점수가 오를 수 있고, 이 실험은 그 가능성을 분리하지 않았으며 지역 일반화(미관측 지역)는 보지 못한다. `NUM_LOWER`도 "수치 표현은 나쁘다"로 일반화하지 않는다.

## 8. 한계

계획서 §13의 12개 항목을 번호 그대로 옮기고, 실행 뒤 확인된 사실을 각 항목 끝에 덧붙였다. 마지막에 이번 보고서에서 추가한 한계를 적었다.

1. **지역 일반화를 보지 못한다.** 층화 CV에서는 같은 지역이 학습·검증에 모두 있다. 수치 정수 축 분할이 지역 외우기로 기능해도 점수가 오를 수 있다. 미관측 지역(geo2/geo1 Group) 성능은 이 판정의 범위 밖이며 새로 측정하지 않았다. 기존 geo2 인용값(`LGBM` O 0.582827, P 0.582545, N 0.545694, LR-C 0.565146)은 T8/T9 보고의 인용이며 새 측정이 아니고 팔이 달라 `NUM`과 직접 비교하지 않았고 판정에 쓰지 않았다. 실행 뒤: 학습 Fold에 없는 지역을 가진 검증 행은 Fold당 267~333건이고 그 하위집단 F1은 기술용이다(§2.4).
2. **하이퍼파라미터를 표현별로 다시 조정하지 않았다.** 고정값이 원핫에서 정해졌다면 `NUM`에 불리하거나 유리할 수 있다. 특히 RF의 `max_features=0.1`은 열 수 변화로 후보 특성 수가 크게 달라진다(원핫 12,570~12,623열의 10%인 약 1,260개 대 `NUM` 68열의 10%인 약 6~7개). 차원이 통제된 순수 정보량 차이가 아니다. 후보 특성 수 민감도 팔(RF sqrt, `max_features` 상향)은 두지 않았다: sqrt 팔은 원핫이 퇴화 설정(기존 CV 0.357704)이라 표현 비교로 읽기 어렵고, 상향은 한 요소 정의를 바꾼다. 실행 뒤 `RF_NUM`의 트리 노드 수는 Fold 평균 1,143,422으로 `RF_OH`(518,330)보다 많았다.
3. **`LGBM_NUM`은 `max_bin=255`에 묶인다.** 학습 Fold 고유값이 지역 2는 1,397~1,404개, 지역 3은 11,077~11,126개라 255를 크게 넘어 인접 ID가 합쳐진다(합쳐진 정도는 측정하지 않았다). `max_bin`을 바꾼 시험은 범위 밖이다. 지역 1(고유값 31개)은 영향이 없다.
4. **`LR_NUM`은 표준화한 선형 단조 항**이라 구조적으로 제한적이다. 이 한계 자체가 결과의 일부이며 "수치 표현은 나쁘다"로 일반화하지 않는다. 실행 뒤: `n_iter` 120~144(`LR_OH` 566~595), 수렴 경고 0건(감사 `lr_convergence_warnings`), 지역 열의 절대 계수 비중 0.010220.
5. **지역 3열을 함께만 바꿨다.** 열별 개별 변환(예: geo1만 수치)과 수치+원핫 병행은 범위 밖이다.
6. **단일 시드·단일 분할·단일 기계.** 모든 모델이 `random_state=42`이고 RF/LGBM의 시드 변동을 정량화하지 않았다. 계산량은 Windows 한 대의 단일 스레드 관측이며 Fold 쌍 5개로는 변동 추정이 약하다. 실행 뒤: 같은 입력 반복 측정은 `DT_OH`·`DT_NUM`에서만 했고(학습 시간 변동계수 약 0.9%, 3.3%) 다른 모델의 시간 변동은 모른다.
7. **연령 정책이 모델별로 다르다**(LR·LGBM C, DT·RF·GBC A). 모델 사이의 순위 비교는 하지 않는다.
8. **재사용 OOF의 증거 수준이 다르다.** DT·RF·GBC의 기존 OOF는 로컬 재적합(원 산출물은 `BLOCKED`)이고 LR은 환경 차이가 알려져 있다. 판정은 같은 환경 재적합을 기준으로 해 이 문제를 피했지만 "과거 보고 수치"와의 연결은 Fold 0 대조에 의존한다. 실행 뒤: 대조 6건 모두 PASS이며(§5), `LR_OH`의 Fold 평균 0.688860은 로컬 재적합 값과 같고 원 환경 값 0.688687과 0.000173 다르다.
9. **선택 통계.** 같은 Fold로 이미 여러 번 비교된 자료다. 독립 성능이 아니며 최종 모델 근거가 아니다.
10. **설계자가 확인하지 못한 것과 실행 뒤 상태**(계획 §13-10). (a) 층화 Fold별 지역 미관측 건수: Fold별 306, 287, 333, 267, 314건(§2.4). (b) 지역 열 고유값 수와 최대값: 학습 Fold 고유값은 지역 1 31개, 지역 2 1,397~1,404개, 지역 3 11,077~11,126개이고 지역 값 최대는 12,567(감사 확인, 2^24보다 작음)이다. 문서의 "약 1.2만"은 이 합(원핫 지역 열 12,528개)에 부합한다. (c) 지역 외 열 수: `DT_OH` Fold 0에서 12,593 − 12,528 = 65개이고 `NUM`은 68열(+지역 3)로 가정(68~69)과 일치한다; 텍스트 원핫 열 수 자체는 따로 확인하지 않았다. (d) LGBM 스레드 수 변경 시 확률 일치: 단일 스레드 재적합이 기존 OOF(계획서 기준 기존 `n_jobs`=2)와 `LGBM_OH`·`LGBM_NAT` 모두 최대 절대 차 0.0으로 일치했다(Fold 0). (e) `NUM` 행렬 밀도: CSR 학습 행렬 밀도 0.256379~0.405257(LGBM 포함 `NUM` 팔 전체 Fold)이고 프로세스 간 시계는 공통이었다(설계 `clock_check.common`=true). (f) 시간 추정: `fit-all` 실제 소요 3690.3초(약 61.5분)로 계획서의 잠정 45~90분 안이다.
11. **컨테이너와 메모리 측정의 한계.** `OH`·`NUM`을 같은 CSR로 고정해 경로 차이를 맞췄지만, 이는 sklearn의 희소 분할기를 약 70열 행렬에도 쓰는 것이라 수치 우선 파이프라인이 자연스럽게 쓰는 dense 경로의 계산량이 아니다. `LGBM_NUM` vs `LGBM_NAT` 계산량은 컨테이너가 섞여 태그를 붙이지 않았다(선택 보조 팔 `LGBM_NUM_DENSE`는 승인 범위 밖이라 실행하지 않았다). 메모리는 20 ms 샘플링의 하한 추정이고 16 MiB 미만 증가분은 비교에서 제외한다. 실행 뒤: `sampling_limited`는 인코딩+학습 구간 기준 0건(인코딩 단독 구간 55/55, 예측 구간 43/55 fit은 샘플 50개 미만이고 예측 구간 RSS 증가분은 55 fit 모두 0.0), `peak_wset` 보조 지표 `FLOOR_LIMITED` 45/55건, 메모리 태그 부여 0건.
12. **인코딩 시간의 왕복 비용.** 공통 전처리가 지역을 문자열로 만든 뒤 `NUM`은 다시 정수로 바꾸는 왕복이 있다. 인코딩 시간은 순수 표현 비용이 아니다(정규화와 표현 변환 단계는 `analysis.json`에 분리 기록). 실행 뒤: 인코딩 시간 비율의 7개 비교 중앙값은 0.967681~1.067616로 태그를 붙이지 않았다.

**이번 보고서에서 추가한 한계.**

- **계산량 측정은 오염됐다(§4).** LR의 시간 비율(학습·예측·종단)은 전부 noisy 쌍에서 나왔고 LGBM은 Fold 3·4 쌍이 섞였으며 LR에는 깨끗한 쌍이 없다. 모델 파일 크기·행렬 저장 크기 비율은 결정적 값이다. 시간 비율은 정밀한 값으로 인용하지 않는다. 깨끗한 환경에서의 재측정은 하지 않았다. 전원 관리 옵션은 균형 조정이며 고성능이 아니다.
- 메모리 계산량 태그가 7개 비교 모두 없다(위 11번). 메모리 축의 비교 결론은 없다.
- §3.5의 경계 근접 기준과 §4.3의 "깨끗한 쌍" 민감도 기준은 결과를 확인한 뒤 보고서 작성자가 정했다. 사전등록 규칙이 아니고 판정 라벨에 쓰이지 않았다.
- 성능 태그의 임계(|Δ| 0.003, 승수 4/5, ΔRecall3 −0.01, 3→1 상대 +10%·절대 +30건)와 계산량 비율 임계(0.5, 2.0)는 사전 승인된 제안값이다. Fold SD가 LR 약 0.0015, LGBM 약 0.0033~0.0037, DT 0.0045~0.0056, GBC 0.0044~0.0051, RF 약 0.0038~0.0055라 트리 모델에서는 0.003이 Fold 변동폭 안이다. 그래서 Fold 승수를 함께 요구한다. 어느 태그도 유의성 검정이 아니다.
- 3→1은 풀링 건수가 수백 건 규모이고 `SAFETY_3to1` 표시는 건수 차 30건 이상일 때만 켜진다. 3→1 허용 상한은 오류 비용 판단이라 이 연구에서 정하지 않았다(T29 사용자 결정 항목).
- 계획 §3.3이 적은 대로 재적합한 `OH`/`NAT` OOF를 기준으로 삼았으므로 과거 보고 수치와는 대조(§5)를 통해서만 연결된다.
- 독립 감사(PASS_T31)는 학습 행렬이 저장돼 있지 않아 LR 기울기·트리 구조·학습 Macro F1로 학습 입력을 **간접 증명**했다. 이 공개 보고서의 독립 검토(PASS_WITH_DEFECTS, high 0 / medium 1 / low 10)의 지적은 이 판에 모두 반영했다.
- 단위 테스트 수치는 조정자가 전달한 값이며 이 작업에서 재실행하지 않았다: tests.test_geo_code_encoding 62개 통과·skip 0, 전체 discover 1,155개 OK·skip 33 (조정자가 전달한 값을 옮긴 것이다. 이 보고서 작성 중 다시 실행하지 않았다.)
- 홀드아웃은 접근하지 않았다. 이 결과는 새 독립 성능이 아니다. 확인 평가(T29)는 현재 설계 초안만 있는 미승인 상태이며 승인 여부는 별도 사용자 결정이다.
