## 4. 기존 저장 XGBoost 모델 5개의 재추론 예외

1. 기존 T4의 원래 감사기는 [코드](../experiments/model_families/audit.py)에서 `atol=1e-7`, `rtol=0`을 사용했다. 당시 해당 환경의 재추론 최대 확률차는 보고서상 `1.11e-16`이었고 PASS로 저장됐다.
2. Windows 교차환경에서 **동일 원래 저장 모델** 20개에 대한 진단은 **XGB 5개만** 이 기준을 초과했다고 보고했다. 최대 절대차는 `1.1920928955078125e-7`; **예측 등급은 20개 모두 동일**했고 입력 행렬 SHA 역시 같다고 보고했다. 나머지 XGB 5개와 LGBM 10개는 해당 기준 통과다.
3. **새 Windows 학습 모델** 20개는 로컬 환경 내부 원래 감사기로 전수 재추론 PASS였다. 이는 **원래 저장 모델을 Windows에서 로딩해 비교한 미달**과 다른 검증이다.
4. 사전 허용오차를 사후 늘려 `PASS`로 바꾸지 않았다. 확률 재현 미달을 분류 성능 악화나 과거 연구 무효로 과장하지 않고, 분류 불변만으로 확률의 엄격 일치를 주장하지 않는다.

첨부 본문에는 미달한 XGB 5개 모델의 정확한 A/C·Fold 식별자가 없다. **어느 모델인지 추측하거나 모두 한 설정이라고 간주하지 않는다.** 전수 재추론 상세 로그는 아래 7절의 비공개 보관 대상으로 둔다.

## 5. LR 재현 미달과 원인 가설

| 대표 실행 | 원래 F1 | Windows F1 | 차이 |
| --- | ---: | ---: | ---: |
| baseline_v1/lr | 0.683676986 | 0.683787098 | +0.000110112 |
| age995/C | 0.688687373 | 0.688859847 | +0.000172474 |
| interactions/G2 | 0.690993134 | 0.690970798 | -0.000022337 |

- 동일 Windows 내부의 baseline LR과 personal-none OOF는 바이트 일치. 기존·로컬 입력의 인코딩 열 수 5 Fold가 모두 일치했고, 보고서상 전처리·sampling 메타데이터 **660개 대조 항목 모두 일치**했다.
- 별도 Fold0 실험에서 CSR은 동일한 상태로 `OPENBLAS_CORETYPE`만 Haswell→Nehalem 변경했을 때 LR 반복수 **568→549**, 예측 **170건 변경**. 이는 LR이 수치 커널에 민감하다는 직접 증거지만 **과거 Linux와의 모든 차이를 BLAS 단독 원인이라고 입증하지는 않는다**.
- 기존·로컬 C의 전체 3→1은 **452→455건**, G2는 **478→474건**이었고, G2가 C 대비 F1을 높이면서 3→1 오류도 늘리는 **방향성은 재현**됐다. 과거 OOF 원수치와 새 OOF 원수치는 구분하여 보존한다.
- 원래 계수·정확한 Linux BLAS/wheel/CPU 조건이 없어 LR의 엄격 수치 동일성은 **22개 실행 모두 `DIFFERENCE_UNDER_REVIEW`**로 유지한다. CSV의 LF↔CRLF 직렬화 차이는 바이트 SHA에 영향을 주지만 LR 예측 차이의 원인으로 단정하지 않는다.

## 6. 연구 결론과 수정 금지 범위

- 기존 T4의 **원래 개발 CV 결과**, OOF, 저장 모델·원래 감사 `PASS`, 보고서, 파라미터 및 기존 LR-C 후속 연구 기준은 그대로 보존.
- 새 T4 모델 계열 A/C 비교 결과는 엄격 수치 재현되었으나, 미해결된 교차환경 확률 동일성 한계를 후속 작업에 인계.
- **홀드아웃 재평가·신규 튜닝·후보 재선정·확률 허용오차 사후 완화·G1~G5 또는 T6 결과의 자동 결합을 수행하지 않음.**
- 현재 결과는 과적합·데이터 누수의 새로운 증거나 엄격한 환경불변 재현 증명으로 과장하지 않는다.

## 7. 최소 후속 확인 및 증거 위치

1. **학습 없이 로컬 전수 진단 파일 확인:** 기존 T4 원본 XGB 5개 미달 모델의 실험 ID·Fold·허용오차 초과 행 수·최대 오차·모델 및 행렬 SHA·20개 모델 예측등급 변경 0건을 상세 로그에서 확인한다. 본문에 없는 개별 모델 ID는 미확인 상태로 둔다.
2. **LR은 대표 Fold·환경 기록만 우선:** 과거 Linux의 정확한 BLAS·wheel·CPU 정보와 LR 계수가 이미 보존되어 있다면 원래 A/C 대표 Fold에 한해 대조한다. 없다면 검토 상태를 유지하고 **22개 LR/190 Fold 전체를 재실행하지 않는다**.
3. **증거 참조만 보존:** 사용자 제공 `REPRODUCTION_REPORT.md`와 로컬 `original_vs_local.csv`, `fold_comparison.csv`, `confusion_matrix_comparison.json`, `parity_policy.json`, `source_and_data_sha256.json`, `environment.json`, `audits/original_*`, `t4_receive_receipt.json` 및 T4 확률 전수 진단 로그. 로컬 파일의 실제 보관 경로·SHA 세부값은 첨부 본문에 전부 없으므로 이번 공개 문서에서 **독립 확인했다고 쓰지 않는다**. 비공개 OOF·모델·Fold manifest·로그 원본은 Git에 올리지 않는다.

**마무리 판정:** 별도 로컬 재현은 충분히 수행된 상태다. 남은 확인은 비학습 로그·환경 기록 중심이며, 현재 T4 검증 결과·후보·홀드아웃 경계를 변경할 근거는 없다.
