## 3. 실행 방식 (2·3단계)

- 모델 정의는 원래 T6 `experiments/geo_ablation/run.py`의 `make_pipeline`과 `config.json`을 **변경 없이** 사용했다. LR C=1, lbfgs, max_iter=1500, tol=1e-4, random_state=42, 단일 스레드이며, 분할·전처리·피처 정책도 동일하다.
- 원래 실행기는 구성 단위로 실행하고 기존 디렉터리를 거부하므로 Fold 단위 재개가 불가능하다. 그래서 새 실행기 `experiments/geo_ablation_local_repro/run.py`를 추가했다. 각 Fold가 끝나는 즉시 다음을 수행한다.
  - 모델, 예측 확률, Fold 지표를 저장한다.
  - SHA-256과 원장(`ledger.json`, `attempts.jsonl`, `run.log`)을 기록한다.
  - 재로딩으로 예측을 검증한다.
  - 별도 `backup/` 복사본을 만들고 SHA를 대조한다.
- 완료 Fold는 재실행 시 해시만 확인하고 재학습하지 않는다. 실제로 Fold0 재실행에서 스킵을 확인했다. 설계와 소스는 학습 전 `design.json`과 seal로 고정했다(학습 커밋 `2b615414`).
- 환경: Python 3.13.5 / numpy 2.3.5 / pandas 2.2.3 / scipy 1.17.0 / scikit-learn 1.8.0 / joblib 1.5.3 / threadpoolctl 3.6.0. 원래 동결 환경과 동일하다. 전체 학습 시간은 약 6분이다.
- 비공개 산출물: `local_reproduction/T6R_20261014_local/`. 검증된 ZIP 백업은 `T6R_20261014_archive/`에 있다(멤버 331개, ZIP SHA `9474311d…fd2a0`). 원시 데이터·모델·OOF·manifest는 Git에 넣지 않았다.

## 6. 해석 범위

- **랜덤(Stratified) CV:** 지역 변수를 하나씩 제거할수록 성능이 단조롭게 떨어진다(C 0.689 → R12 0.653 → R1 0.593 → R0 0.458). 실제 3등급 Recall과 3→2 오류도 악화된다. 3→1은 줄지만 3→2가 훨씬 크게 늘어 안전성 개선으로 볼 수 없다.
- **미관측 2차 지역(geo2 Group):** R1(geo1만 사용)이 C보다 평균 +0.019, 5/5 Fold에서 높다. 다만 SD가 0.018~0.020이고, 실제3 Recall은 C와 비슷하다(51.9% vs 52.1%). C 행 단위 OOF가 없어 같은 행 전이와 오류 수정은 산출하지 못했다.
- **미관측 1차 지역(geo1 Group):** R0이 C보다 평균 +0.062, 5/5 Fold에서 높다. 실제3 Recall도 0.6%에서 13.8%로 오른다. 그러나 3→2가 여전히 85.6%이고 절대 성능은 0.43 수준에 그친다. 3→1은 170에서 391로 늘었다.
- 지역 변수에는 **랜덤 성능과 미관측 지역 일반화 사이의 교환관계**가 관찰된다. 이것은 개발 데이터 안의 기술적 CV 결과다. 지역 누수·과적합의 인과적 증명, 통계적 유의성, 외부 지진·홀드아웃 성능을 주장하지 않는다. 최종·배포 모델은 변경하지 않으며 C를 기준선으로 유지한다.

## 7. 한계와 다음 단계

1. C geo2/geo1의 행 단위 OOF와 T5 C 모델 10개가 로컬에 없다. 그래서 Group CV의 같은 행 오류 전이, C 대비 수정/신규 오류, C 모델 재로딩은 하지 못했다. T5 비공개 패키지(`earthquake_C_baseline_recovery_private_20261014.zip` 등)를 회수하면 학습 없이 보완 감사가 가능하다.
2. 원래 T6의 비공개 증거가 회수되면, 기존 인계문에 따라 T6R과 **별도로** 감사한다. 원래 결과와 T6R 결과는 합산하거나 소급하지 않는다.
3. 저장 모델 재로딩은 독립적인 재학습 재현이 아니다.
